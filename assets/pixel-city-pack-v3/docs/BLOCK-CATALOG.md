# Каталог блоков и runtime-правила

## Координатная модель

Карта — целочисленная квадратная сетка. Одна клетка равна 8×8 пикселей при масштабе 1×. Координата `(x, y)` означает левый верхний угол клетки. Карта не хранит пиксельные координаты.

Клетка может одновременно содержать:

```text
terrain -> surface -> overlay[] -> object footprint -> visual sprite -> UI
```

Например, мостовая клетка содержит `terrain=water`, `surface=road`, а на внешнем краю — `overlay=bridge-side-horizontal`.

## Тайлы 8×8

| ID | Слой | Назначение | Правило |
| --- | --- | --- | --- |
| `grass` | terrain | Основная суша | Заполняет свободные клетки мира |
| `water` | terrain | Река или озеро | Образует непрерывные области; нельзя ставить здание |
| `road` | surface | Чистый асфальт без разметки | Дорога любой формы собирается повторением тайла |
| `pavement` | surface | Платформа здания/площадь | Заполняет footprint до отрисовки здания |
| `path-brown` | surface | Пешеходная грунтовая тропинка | Соединяет вход, парк, площадь и дорогу; не пересекает воду без отдельного моста |
| `curb` | overlay | Граница асфальта и суши | Ставится только на внешнем ребре road-cell; поворачивается/отражается |
| `crosswalk-horizontal` | overlay | Переход людей слева направо | Ставится поверх road; полосы визуально вертикальные |
| `crosswalk-vertical` | overlay | Переход людей сверху вниз | Ставится поверх road; полосы визуально горизонтальные |
| `road-marking-horizontal` | overlay | Опциональный горизонтальный штрих | Набор содержит его, но демонстрационный город разметку не использует |
| `road-marking-vertical` | overlay | Опциональный вертикальный штрих | Размещается только явно, не рисуется кодом |
| `bridge-side-horizontal` | overlay | Перила вдоль горизонтального края моста | Для верхней/нижней стороны; нижняя получается отражением |
| `bridge-side-vertical` | overlay | Перила вдоль вертикального края моста | Для левой/правой стороны; правая получается отражением |

## Как собирается дорога

1. Генератор создаёт множество `roadCells`.
2. В каждую клетку кладётся один `road` 8×8.
3. Для четырёх соседей проверяется наличие дороги.
4. Если сосед не дорога и текущая клетка не мостовая — на границе размещается повернутый `curb`.
5. Если сосед тоже дорога, граница остаётся открытой. Так автоматически появляются прямые участки, повороты, Т-соединения и перекрёстки.

Запрещены ассеты `intersection`, `corner`, `t-junction`: количество комбинаций должно определяться данными соседей, а не картинками.

## Пешеходный переход

Переход — overlay 8×8, который повторяется на нескольких road-cells поперёк проезжей части. Он размещается перед перекрёстком, но не в центральной конфликтной области. Ориентация названа по направлению движения пешехода.

## Мост

Последовательность слоёв:

```text
water 8×8 -> road 8×8 -> bridge-side 8×8
```

Вода остаётся логическим terrain под мостом. Асфальт используется обычный. `curb` на мостовых клетках не ставится — его заменяют перила. У горизонтального моста перила идут по верхней и нижней внешним сторонам; у вертикального — по левой и правой.

## Малые объекты

| Объект | Canvas | Footprint | Anchor |
| --- | --- | --- | --- |
| Дерево, фонарь, столб | 8×16 | 1×1 | `(4,16)` |
| Скамейка вертикальная | 8×16 | 1×1 | `(4,16)` |
| Скамейка горизонтальная | 16×8 | 2×1 | `(8,8)` |
| Урна, клумба, гидрант, ящик, боллард | 8×8 | 1×1 | `(4,8)` |
| Велопарковка | 16×8 | 2×1 | `(8,8)` |
| Фонтан, стол для пикника | 16×16 | 2×2 | `(8,16)` |
| Остановка | 16×16 | 2×1 | `(8,16)` |
| Машина вертикальная | 8×16 | 1×2 | bottom-center |
| Машина горизонтальная | 16×8 | 2×1 | bottom-center |

Спрайт дерева или столба выходит на одну клетку вверх, но занимает землю только в нижней клетке.

Props не содержат землю, траву или pavement. Генератор сначала выбирает допустимую surface-клетку, затем ставит независимый prop и сортирует его по bottom-center anchor. На дороге допускаются только профильные объекты: машина, остановка у бордюра, гидрант или боллард рядом с краем; скамейки, клумбы и столы размещаются на pavement, площади, парковой траве или у тропинки.

## Здания и стадии

Каждое здание имеет фиксированные `spriteSize`, `footprintCells` и `anchorPx`. Все пять стадий используют один canvas и один anchor:

1. подготовленная земля;
2. фундамент;
3. каркас;
4. почти готово со строительными лесами;
5. завершённое здание.

Статусы задачи отображаются напрямую:

| Статус | Стадия |
| --- | --- |
| Планирование | 1 |
| Начало работы | 2 |
| Прогресс работы | 3 |
| Тестирование | 4 |
| Завершено | 5 |

## Порядок отрисовки

1. Terrain: трава, вода.
2. Surface: дорога, pavement, тропинка.
3. Overlay: curb, переход, опциональная разметка, перила моста.
4. Платформы/footprints задач.
5. Здания, машины и малые объекты, отсортированные по мировому `anchorY`, затем `anchorX`.
6. Подсветка района, выбор задачи и UI.
