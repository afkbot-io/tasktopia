# Инструкция для ИИ по генерации и заполнению карты

## Цель генератора

ИИ создаёт не изображение города, а валидную карту из дискретных клеток и объектов. Рендерер сам выбирает PNG по `assetId`. Любое решение сначала проверяется геометрически, затем оценивается эстетически.

## 1. Детерминизм и чанки

- Вход: `countrySeed`, `cityId`, координаты чанка.
- Рекомендуемый чанк: 64×64 клетки.
- Один и тот же seed всегда даёт одинаковые terrain, дороги и свободные участки.
- Генерируются только видимые и соседние чанки; данные построенных районов сохраняются и больше не перегенерируются.

## 2. Terrain

1. Заполнить сушу `grass`.
2. Сгенерировать реки непрерывным random walk или noise-ridge шириной 4–8 клеток.
3. Не допускать одиночных водных пикселей, диагональных разрывов и тупиков длиной 1 клетка.
4. Озеро должно иметь связную область и минимум 4×4 клетки.

## 3. Дорожный граф

- Городская магистраль имеет ширину 4 клетки; локальная дорога может иметь 2 клетки.
- Сначала строится логический граф узлов, затем A* прокладывает клеточный путь.
- Стоимость поворота выше стоимости движения прямо, поэтому дорога не должна «дребезжать».
- Дорога может пересекаться с другой дорогой простым объединением `roadCells`.
- Никакие готовые спрайты поворотов и перекрёстков не выбираются.
- Тупик допустим только у участка, парковки или служебного здания.

После построения road-set для каждой клетки вычисляется четырёхбитная маска соседей `N/E/S/W`. Маска нужна логике навигации, но не выбирает отдельный дорожный PNG.

## 4. Бордюры, переходы и разметка

- `curb` ставится на ребре road-cell только когда соседняя клетка не road.
- На общей границе двух road-cells бордюр запрещён.
- Переход ставится перед перекрёстком на прямом подходе, а не в центре пересечения.
- Переход повторяется поперёк всей ширины дороги.
- Разметка по умолчанию выключена. Если тема города её включает, используются только `road-marking-horizontal/vertical` 8×8.
- Рендерер не рисует линии примитивами.

## 5. Мост

Если найдено пересечение road и water:

1. Пометить клетки как `bridgeCells`.
2. Сохранить под ними `terrain=water`.
3. Положить обычный `road` как surface.
4. Не использовать curb.
5. Поставить `bridge-side-horizontal` на внешние верхнее/нижнее ребро горизонтального моста или `bridge-side-vertical` на левое/правое ребро вертикального.
6. Минимальная длина моста равна ширине водной области плюс одна береговая клетка с каждой стороны.

## 6. Район и свободные участки

При создании спринта:

- выбрать связную область рядом с существующей дорогой;
- стартовый размер — не менее 14 свободных клеток плюс дорога;
- форма не обязана быть прямоугольной, но должна быть связной по сторонам;
- зарезервировать 20–30% площади под рост;
- минимум один край района должен касаться дороги;
- footprint другой задачи и water являются hard obstacles.

## 7. Выбор здания для задачи

Сначала применяются hard constraints:

- footprint полностью свободен;
- не пересекает water, road и другой footprint;
- находится в районе задачи;
- имеет доступ к дороге через pavement или path;
- unique-здание ещё не существует в городе.

Затем кандидатам начисляются soft scores:

```text
score = needInDistrict
      + needInCity
      + categoryDiversity
      + visualDiversity
      + roadAccess
      + landmarkBonus
      - duplicatePenalty
      - isolationPenalty
```

Рекомендуемая связь оценки задачи и масштаба:

| Оценка | Предпочтение |
| --- | --- |
| 1 | коттедж, таунхаус, малый объект |
| 2 | дом 3×2, небольшой магазин |
| 3 | малый жилой дом, крупный магазин, банк |
| 6 | высотка, школа, полиция, пожарная часть, клиника, мэрия |

Это предпочтение, а не единственный допустимый вариант. Малую задачу можно представить несколькими маленькими объектами позже, но один task id остаётся владельцем группы.

## 8. Размещение footprint и anchor

Для здания сначала задаётся целочисленный `footprintOriginCell`. Нижний центральный world anchor вычисляется из точного центра footprint, поэтому корректно поддерживаются площадки нечётной ширины 5×N и 7×N:

```text
anchorWorldX = footprintOriginX * 8 + footprintWidth * 4
anchorWorldY = (footprintOriginY + footprintHeight) * 8
screenX = anchorWorldX - anchorPxX
screenY = anchorWorldY - anchorPxY
```

Сначала рисуется pavement footprint, затем спрайт. Все объекты сортируются по `anchorWorldY`, затем `anchorWorldX`.

Высотки могут закрывать объекты севернее. Это нормально. Они не должны закрывать объекты южнее с большим anchorY.

## 9. Тропинки и входы

- От входа здания до ближайшей дороги строится короткий путь из `path-brown` или pavement.
- Тропинка предпочитает прямые участки и максимум два поворота.
- Она не проходит через footprint, road или water.
- Для парка допускаются ветвления и кольца.
- Если нужна переправа через воду, требуется отдельный пешеходный мост; обычная тропинка поверх water запрещена.

## 10. Декор

- Декор выбирается после дорог, footprints и тропинок, чтобы не блокировать обязательный путь.
- Скамейки и столы ставятся рядом с path/pavement, но не перекрывают вход здания.
- Урна ставится рядом со скамейкой, остановкой или общественным зданием; несколько урн не должны стоять в соседних клетках.
- Клумба и фонтан требуют свободную площадь и не ставятся на road/water.
- Остановка располагается у прямого участка дороги со стороны бордюра; её visual sprite не меняет roadCells.
- Гидрант размещается у дороги в жилой/служебной зоне, велопарковка — рядом с коммерческим или общественным зданием.
- Все props используют `anchorPx` из manifest и участвуют в общей сортировке по `anchorWorldY`.

## 11. Машины

- Машина появляется только на road-cell и не занимает curb/crosswalk клетку.
- На вертикальном сегменте используется canvas 8×16, на горизонтальном — 16×8.
- Горизонтальный и вертикальный спрайты — две согласованные, но независимо нарисованные проекции одной модели под общий слегка наклонённый ракурс.
- Цвет выбирается детерминированно по vehicle id.
- При смене направления выбирается другой sprite id; CSS/Canvas rotation запрещён, потому что он ломает перспективу и пиксельную сетку.

## 12. Стадия задачи

```text
PLANNING  -> stage-1
STARTED   -> stage-2
IN_PROGRESS -> stage-3
TESTING   -> stage-4
COMPLETED -> stage-5
```

При обновлении меняется только sprite id. Footprint, anchor и координаты остаются прежними.

## 13. Минимальная структура данных

```json
{
  "cell": { "x": 42, "y": 30 },
  "terrain": "grass",
  "surface": "pavement",
  "overlays": [],
  "object": {
    "taskId": "task_123",
    "assetId": "highrise-glass-stage-3",
    "footprintOriginCell": [40, 27],
    "footprintCells": [4, 3]
  }
}
```

## 14. Финальная валидация карты

- Нет пересечения footprints.
- Все дороги связаны с городской сетью либо явно являются тупиком назначения.
- У каждого здания существует путь к дороге.
- Нет curb между двумя road-cells.
- Нет тропинки или здания на water.
- На мосту есть road и bridge sides, но нет curb.
- Все asset ids существуют в manifest.
- Все стадии задачи используют одинаковый canvas/anchor.
- В каждом районе есть минимум две категории зданий, если число задач больше трёх.
