# ТЗ: миграция малых, коммерческих и служебных зданий на Tasktopia V5

**Статус:** готово к последовательной реализации
**Дата среза каталога:** 2026-08-12
**Источник истины:** `catalog/buildings.json`
**Базовая клетка:** `8×8 px`
**Обязательные контракты:** `GENERATION-SPEC.md`, visual grammar и building-stage geometry contract

## 1. Результат

После миграции все обычные жилые, коммерческие, городские и служебные здания
должны выглядеть частью одного города с уже принятыми крупными V5-новостройками:

- один строгий фронтально-верхний ракурс;
- видна неглубокая плоскость крыши, но не боковая стена;
- одинаковый человеческий масштаб дверей, окон, техники и этажей;
- пять читаемых стадий прогресса задачи;
- стадии 1–2 собираются общим тайловым конструктором, стадии 3–5 рисуются
  индивидуально;
- поверхность, ограждение, дорога, деревья и городской декор остаются
  отдельными world layers и не запекаются в PNG здания;
- после приёмки семейства его старый sheet и любой процедурный fallback
  удаляются.

Приложенный пользователем высокий служебный корпус используется только как
референс качества пиксельных кластеров, вертикального ритма, крыши и читаемой
конструкции. Его пропорции нельзя механически переносить на одноэтажное кафе,
пожарную часть или коттедж.

## 3. Есть ли у малых и служебных зданий стадии

Да. **Любое здание, привязанное к задаче, имеет ровно пять логических стадий**,
независимо от размера и назначения.

| Стадия | Источник | Что должно читаться |
| --- | --- | --- |
| 1 — план площадки | общий набор тайлов | подготовленный участок, разметка, 2–7 seeded-объектов |
| 2 — фундамент | общий набор тайлов | фундамент, края, арматура, 2–7 строительных объектов |
| 3 — каркас | отдельный AI-authored PNG | назначение уже угадывается по каркасу и пролётам |
| 4 — отделка | отдельный AI-authored PNG | финальная масса здания, незаконченные фасады и близкие леса |
| 5 — готово | отдельный AI-authored PNG | чистое законченное здание без стройматериалов |

То есть для одного семейства вручную принимаются **три**, а не пять картинок.
Runtime всё равно публикует пять PNG.

Исключения:

- пожарная машина, скорая, полицейская машина, фонарь, урна и скамейка — это
  транспорт или ambient prop; строительных стадий у них нет;
- дым, огонь, вода и мигалки — это кадры состояния/анимации, а не стадии;
- парк, если он привязан к задаче, проходит пять стадий как `AREA`-композиция
  из тайлов и props, а не как один PNG здания.

## 4. Геометрический контракт до рисования

Для каждого ключа сначала создаётся `geometry.json`. Рисование без принятой
геометрии запрещено.

Обязательные поля:

```json
{
  "schemaVersion": 1,
  "key": "civic-fire-station-v5",
  "category": "CIVIC",
  "cellSizePx": 8,
  "spriteCanvasCells": [12, 10],
  "physicalFootprintCells": [12, 8],
  "projectedRoofDepthCells": 3,
  "foundationThicknessCells": 2,
  "constructionClearanceCells": 1,
  "entrance": { "side": "S", "offset": 6 },
  "sitePreviewCells": [16, 14]
}
```

Три пространства нельзя смешивать:

1. `physicalFootprintCells` — занятые клетки карты;
2. `spriteCanvasCells` — экранный canvas здания;
3. construction envelope — footprint плюс одна временная клетка с каждой
   стороны под ограждение.

Общие формулы:

```text
spriteWidthPx = spriteCanvasCells.width × 8
spriteHeightPx = spriteCanvasCells.height × 8
anchorPx = [spriteWidthPx / 2, spriteHeightPx]
envelope = [footprint.width + 2, footprint.depth + 2]
stage1or2VisibleDepth = clamp(ceil(footprint.depth × 0.42), 3, 5)
```

Старые размеры не являются обязательными. Если дверь `8×16 px`, крыша и
назначение не читаются на текущем canvas, footprint и sprite canvas нужно
увеличить до генерации исходника. Растягивать уже нарисованный PNG по одной оси
запрещено.

### 4.1. Размерная лестница

| Класс | Типичные объекты | Footprint | Рекомендуемый canvas |
| --- | --- | --- | --- |
| S | киоск, компактное кафе, маленький дом | `4–6 × 3–5` | `32–48 × 32–64 px` |
| M | магазин, клиника, малая пожарная часть | `7–10 × 5–8` | `56–80 × 48–96 px` |
| L | школа, большая пожарная часть, терминал | `11–16 × 8–12` | `88–128 × 64–128 px` |
| Unique | стадион, океанариум, городской ориентир | по композиции | утверждается отдельно |

Это диапазоны для предпроизводства, а не повод автоматически увеличить все
объекты. Итоговый footprint принимает визуальная проверка на городской сетке.

### 4.2. Человеческий масштаб

- обычная дверь: `8×16 px`;
- двойная дверь или парадный вход: `16×16 px`;
- взрослый житель: до `12×20 px` внутри canvas `16×24 px`, с опорой на общую нижнюю линию;
- гараж пожарной части должен быть заметно шире и выше двойной человеческой
  двери и соответствовать 32-px пожарной машине;
- окно обычно имеет читаемую ширину `2–6 px`, но крупный фасад нельзя собирать
  из случайного однопиксельного шума.

## 5. Единый художественный язык

### 5.1. Камера

- фасад всегда параллелен экрану;
- вертикали остаются вертикальными, этажи — горизонтальными;
- крыша видна сверху как неглубокая плоскость;
- полноценная боковая стена, receding facade, изометрический ромб и повёрнутое
  основание запрещены;
- допустимая тёмная правая грань — максимум `max(2 px, 8% ширины)` и только как
  подсказка глубины;
- нижняя точка здания стоит на общем baseline, anchor — нижний центр.

### 5.2. Pixel art

- hard alpha: только `0` или `255`;
- runtime-палитра: не более 32 RGBA-цветов;
- тёмный сине-серый контур, визуально около одного художественного пикселя;
- свет сверху-слева;
- запрещены blur, soft shadow, gradient, antialiasing, текст, логотип и UI;
- детализация проверяется в native `1×`; красивый увеличенный исходник,
  превратившийся в шум после нормализации, отклоняется.

### 5.3. Поверхность и окружение

PNG здания не содержит плитку, траву, асфальт, дорогу, деревья, лавки, урны,
фонари, машины или внешний забор.

- `STONE` и `SERVICE`: непрерывная V5-плитка под physical footprint, перед
  южным входом допускается одноклеточный apron;
- `YARD`: соответствующая району поверхность и отдельная дорожка к входу;
- `ASPHALT`: отдельный service yard/driveway, связанный с коллектором;
- на стадиях 1–4 ограждение строится отдельным overlay по construction
  envelope; двухклеточные ворота совпадают с южным входом;
- на стадии 5 ограждение удаляется полностью.

## 6. Семантика по категориям

### 6.1. Малые жилые здания

Дом должен читаться не только цветом. Используются разные массы: коттедж,
дуплекс, рядный дом, угловой дом, вилла, фермерский дом, блок с двором. Для
каждого — одна сильная особенность и максимум две поддерживающие.

Стадия 3 показывает тот же каркас и ту же ось входа, стадия 4 не меняет форму
крыши, стадия 5 сохраняет footprint и baseline. Двор, дерево и забор участка
не запекаются в дом.

### 6.2. Розница, кафе, офисы и гостиницы

Назначение должно читаться без текста:

- магазин — витрина, canopy и понятный вход;
- кафе/ресторан — широкие окна, навес или терраса внутри силуэта, без столиков
  на внешней поверхности PNG;
- рынок — модульный ряд навесов и центральный проход;
- офис — входная группа и регулярный оконный ритм;
- гостиница — более выраженный вход и повторяемые окна номеров.

### 6.3. Придорожные и производственные здания

- автосервис и склад используют читаемые ворота и сервисный объём;
- парковка — это низкий муниципальный паркинг или ограждённый фронт с въездной
  будкой; пустой асфальтовый прямоугольник не принимается;
- driveway и дорога не входят в PNG;
- фасад ориентирован на южный access point и не может стоять боком к дороге.

### 6.4. Семь АЗС

Каждая АЗС получает самостоятельную композицию, а не перекраску:

- магазин, навес и колонки образуют один фронтальный объект;
- крыша магазина и верх навеса видны под общей камерой;
- нет запечённой дороги и машин;
- compact, city, highway, electric, truck, cafe и wash отличаются массой и
  обслуживаемым транспортом;
- стадия 3 показывает несущие стойки навеса и магазина, стадия 4 — почти
  готовый комплекс, стадия 5 — чистую действующую АЗС.

### 6.5. Пожарные, полиция, медицина и экстренные службы

Служебное назначение кодируется архитектурой, а не подписью.

**Пожарная часть:** 2–4 широких ворот, диспетчерский/служебный объём, возможно
одна сушильная или учебная башня. Compact, standard и large имеют разные
силуэты. На стадии 3 уже должны читаться пролёты ворот. Красный — акцент, а не
сплошная заливка всего фасада.

**Полиция:** защищённый публичный вход, более строгий ритм, отдельный гаражный
или административный объём. Синий — акцент. Районный пункт и управление не
могут быть одной картинкой разного масштаба.

**Клиника/больница/экстренный центр:** ясная входная группа, медицинский
акцент без текста, отделение общественного входа от emergency bay. Нельзя
запекать машину скорой помощи в здание.

**Гражданская защита:** более тяжёлая служебная масса, ворота и защищённый
нижний ярус; не копия пожарной части.

Пожарная техника создаётся отдельным транспортным пакетом. У неё нет пяти
строительных стадий: нужны отдельные east/north/south-проекции, west получается
только из утверждённого east-вида. Дым, огонь и струя воды — отдельные эффекты.

### 6.6. Образование, культура, транспорт и коммунальные службы

- школа/детсад — несколько читаемых крыльев, центральный вход, безопасная
  общественная композиция;
- библиотека/музей/суд — сильная симметрия и парадный вход;
- вокзал/терминал — широкий входной зал и транспортный canopy без встроенных
  автобусов или железнодорожного полотна;
- водоканал/переработка/подстанция — технические объёмы внутри общего
  фронтального силуэта, без хаотичной россыпи мелких props;
- landmark принимает отдельный geometry review и квоту `maxPerCity: 1`.

## 7. Файловый контракт одного семейства

Пример для `civic-fire-station`:

```text
reference/ai-authored/building-stage-study/civic-fire-station-v5/
├── geometry.json
├── sources/
│   ├── stage-3.png
│   ├── stage-4.png
│   └── stage-5.png
└── verified/
    ├── report.json
    ├── stage-{3,4,5}-normalized.png
    ├── stage-{3,4,5}-on-grid.png
    ├── stage-{3,4,5}-on-grid-4x.png
    ├── stage-{3,4,5}-geometry.png
    └── stage-{3,4,5}-geometry-4x.png
```

На одно семейство приходится:

- 3 вручную принимаемых source PNG;
- 1 geometry JSON;
- 1 автоматически формируемый report JSON;
- 15 автоматически формируемых QA preview PNG;
- 5 runtime PNG.

На весь объём 139 семейств:

- **417** новых authored source PNG;
- **139** geometry JSON;
- **139** verification report JSON;
- **2 085** автоматически сформированных QA preview PNG;
- **695** пересобранных runtime PNG;
- обновление 139 записей `catalog/buildings.json`;
- удаление 108 старых sheet-файлов после миграции последнего потребителя.

QA previews являются производными артефактами. Их нельзя считать ручной
перерисовкой или использовать как source.

## 8. Порядок производства

### 8.1. На одно семейство

1. Зафиксировать роль, footprint, canvas, крышу, вход и platform.
2. Выбрать два утверждённых V5-бенчмарка той же категории.
3. Сгенерировать и принять только стадию 5.
4. Передать утверждённую стадию 5 в stage generator и получить стадию 4.
5. Передать утверждённую стадию 4 и geometry contract для стадии 3.
6. Подождать 2–5 секунд между завершёнными запросами генерации.
7. Запустить geometry verifier и просмотреть плиточный preview на `1×` и `4×`.
8. Внести `stageSources`, SHA-256, новую геометрию и `reviewed: true` в каталог.
9. Пересобрать стадии 1–5 и проверить storybook/city block.
10. Только после зелёного gate удалить legacy sheet и fallback.

Нельзя генерировать все стадии одной общей картинкой: это почти всегда даёт
разный угол, baseline и масштаб платформы.

### 8.2. Размер партии

Одна review-партия — не более пяти семейств. Внутри партии каждый source
генерируется отдельно. Следующая партия начинается только после сборки,
автоаудита и визуальной приёмки предыдущей.

Рекомендуемый пилот:

1. `civic-fire-station-compact`;
2. `civic-fire-station`;
3. `commercial-corner-cafe`;
4. `shop-supermarket`;
5. `house-cottage`.

Пилот покрывает гаражные ворота, общественный вход, витрину, низкую широкую
композицию и человеческий масштаб маленького дома.

## 10. Автоматическая проверка

Каждое семейство обязано пройти:

1. canvas и runtime-размеры кратны 8;
2. anchor равен нижнему центру;
3. hard alpha и runtime-палитра не более 32 цветов;
4. одинаковый canvas стадий 3–5;
5. центр отклоняется не более чем на одну клетку, baseline — не более чем на
   один пиксель;
6. стадия 3 занимает 45–80% финальной высоты и узнаваема;
7. стадия 4 сохраняет 85–105% финальной высоты и финальный силуэт;
8. стадия 5 не содержит стройки, забора или окружения;
9. вход в PNG совпадает с `entrances` в пределах одной клетки;
10. roof/top plane присутствует и имеет тот же угол на стадиях 3–5;
11. нет боковой стены, повёрнутой платформы и искажения aspect ratio;
12. stage 1–2 детерминированы seed, но различаются между задачами деталями;
13. все пять runtime-файлов существуют и визуально различимы;
14. старый sheet больше не достижим из каталога или build script.

Код не может доказать корректность ракурса и идентичность здания. Поэтому
ручная визуальная проверка в native `1×` остаётся blocking gate.

## 11. Storybook и интеграционная приёмка

Для каждой review-партии storybook показывает:

- пять стадий каждого семейства подряд;
- индивидуальный preview стадий 3–5 на V5-плитке;
- dark/checkerboard preview без окружения;
- один плотный городской квартал с дорогой 2 и 3 клетки;
- двери `8×16 px` рядом с жителем до `20 px`, без изменения канонического размера двери;
- служебные ворота рядом с соответствующей машиной;
- плиточную/platform-маску и construction envelope отдельными overlays.

Интеграционный сценарий создаёт задачи со всеми пятью статусами, проверяет
смену спрайта через realtime update, отсутствие пересечений footprint,
доступность южного входа, квоты городских служб и отсутствие старого ассета в
сетевых запросах.

## 12. Release gate

Минимальный набор команд после каждой партии:

```bash
npm run assets:build
npm run assets:verify
npm run assets:storybook
npm run typecheck
npm run lint
```

Перед релизом полного этапа дополнительно:

```bash
npm test
npm run test:worldgen
npm run test:world-validation
```

`test:worldgen` и browser validation запускаются в подготовленном PostgreSQL/E2E
окружении. Нагрузочная проверка остаётся отдельной и не запускается параллельно
с функциональной генерацией.

Этап завершён только если:

- мигрированы все 139 семейств;
- в scope нет `sheet`, процедурного renderer и `reviewed: false`;
- все 417 source PNG имеют закреплённый SHA-256;
- все 695 runtime PNG собраны из принятого контракта;
- storybook и тестовый город не содержат старого ракурса, неправильной
  платформы, плавающих дверей или несовместимого масштаба;
- старые source sheets удалены физически, а не скрыты fallback-веткой.
