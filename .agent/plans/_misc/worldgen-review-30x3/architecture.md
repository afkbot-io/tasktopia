# Architecture notes

## Current boundary

`AppService` синхронно создаёт cities/districts/tasks в SQLite. Геометрия и terrain детерминированы country seed. Клиент получает чанки и рисует Pixi layers.

## Target boundary

- Один fixture builder описывает контент, но использует только публичные методы `AppService`.
- Отдельный read-only audit вычисляет пространственные метрики из DTO/SQLite и падает при нарушении инвариантов.
- Demo seed и integration review используют один сценарий, чтобы визуальная карта соответствовала проверенному миру.
- Проверки не зависят от случайных UUID и времени; геометрия зависит только от seed и порядка команд.

## Alternatives considered

- Только увеличить `worldgen-scale-smoke`: отклонено, потому что текущий smoke распределяет 250 задач иначе и не доказывает качество одного плотного города.
- Генерировать визуальный fixture напрямую SQL: отклонено, потому что это обходит реальные application rules.
- Делать отдельную debug-страницу: пока избыточно; достаточно отдельной базы и обычного UI.

## Rollout / rollback

Изменения fixture обратимы. Перед заменой локальной базы текущий файл переносится в именованный backup. Изменения генератора должны сохранять публичные API/MCP contracts.
