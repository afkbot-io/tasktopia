# ADR 0004: единый pointer-контур карт и безопасный PWA shell

- Статус: принято
- Дата: 2026-08-28

## Контекст

PLANET, COUNTRY и CITY имели три разных mouse/wheel-контура. Touch drag и pinch
работали непоследовательно, а часть обработчиков пыталась отменять passive wheel.
Приложение публиковало manifest без полного installability-контракта и не имело
service worker. Кэширование авторизованных API или Socket.IO недопустимо: карта и
задачи являются пользовательскими данными.

## Решение

- Все три renderer используют общий `MapPointerGestureTracker`: один pointer даёт
  incremental pan, два — midpoint pan и непрерывный scale. Renderer по-прежнему
  владеет camera bounds, уровнем детализации и переходом между уровнями.
- Pointer capture является улучшением, а не условием работы: Safari и synthetic
  streams могут его не предоставить. Интерактивные подписи и кнопки исключаются
  из начала жеста, а состоявшийся drag подавляет следующий click.
- Canvas/SVG остаются pixel-art поверхностями: smoothing выключен, CITY ограничивает
  device pixel ratio значением `2`, COUNTRY компонуется один раз в нативный raster,
  PLANET сохраняет crisp square sprites.
- PWA precache содержит только публичный application shell, manifest, иконки и
  content-addressed bundles. `/api`, `/mcp`, `/socket.io` и `/health` никогда не
  попадают ни в precache, ни в runtime cache. Offline navigation возвращает shell,
  но не имитирует авторизованные данные.
- Имя PWA-кэша включает revision, вычисленную из bundle filenames и содержимого
  стабильных public-файлов. `sw.js` и manifest всегда revalidate; managed static
  release публикует их атомарно вместе с bundle.
- Safe areas задаются на корневом shell, мобильные основные controls имеют touch
  target не меньше `44×44`, модальные панели используют `100dvh`.

## Последствия

Уровни карт сохраняют независимые проекции и сетевые контракты из ADR 0003, но
получают одинаковую мобильную механику. Установленное приложение открывается без
сети до shell/auth-state; приватные данные без сети намеренно недоступны.

Web Push не входит в этот ADR: подписка, VAPID-ключи, серверная доставка и revoke
оформлены отдельной зависимой задачей. Запрос системного разрешения допускается
только после явного действия пользователя в профиле или заметном post-login
предложении, а не автоматически при каждом входе.

## Отклонённые варианты

- Отдельные touch-реализации для Pixi, DOM canvas и SVG: расходятся по порогам и
  повторяют ошибки capture/cancel.
- Cache-first для API: показывает устаревшие чужие или отозванные данные после
  смены сессии.
- Автоматический permission prompt после авторизации: не объясняет ценность,
  хуже восстанавливается после отказа и не соответствует iOS user-gesture flow.
