# Public spaces and sprint growth — local verification

Scope: append-only sprint overflow, stable task-owned park variants, compact
fountain/monument stages and their city integration. Branch
`codex/task-14-block-runtime-integration`, base `b42fe594`, dirty integration
worktree. This is not a release report or a statement that all earlier requests
are finished. No production data, provider tasks or deployment were changed.

## Implemented contracts

- New blocks remain owned by the requested sprint. The city's street graph
  stays connected; previous parcels, roads, tasks and permanent sites stay put.
  CITY hit areas use actual territory; PLANET chooses an owned occupied block.
- Fifteen PARK variants share one enum through MCP, server validation, client
  labels and migration `0027`. New automatic selections are persisted, not
  rerolled on stage updates. No task is created as decorative filler.
- Compact public spaces use compatible residual or unreserved building lots;
  `urban-large` receives a real `17×17` parcel in `park-grand`. The schema stores
  semantic blocks/slot overrides, not extra per-tile park rows.
- Two AI centerpiece families provide six accepted native `16×16` layers.
  Their frame, `2×2` footprint, anchor and foundation are stable through stages
  `5→4→3`. Stages 1–2 retain the shared site kit. Ground remains procedural.
- A finished decoration plan reserves paths and object footprints before stage
  reveal. The park display root sorts at its ground baseline; content, hit area
  and tooltip retain their correct world coordinates.

## Visual evidence and known boundaries

The isolated, non-reseeded `compact_public_spaces_20260905` fixture contains
30 tasks in three sprints: 11 buildings and 19 public spaces, all 15 variants,
fountain/monument stages 3/4/5 and one large park. It is generated by AppService,
not by manual sprite placement. Screenshots live in
`screenshots/compact-public-spaces/`: city, both centerpiece stage sequences,
large park, country and planet.

[Browser report](evidence/public-spaces/browser.json): desktop checks passed
task clicks and canonical responses, one scene, one country overview, one
planet atlas and no viewport/chunk fetches while panning or returning from the
overview. The 390×844 responsive pass selects actual country/city cards, opens
a pocket-park task and checks no horizontal overflow. `city-mobile.png` records
the resulting layout. This is not touch-device emulation or a Safari/PWA test.
Page, application-console and network error arrays are empty. Chromium
software-GPU `ReadPixels` screenshot warnings are retained separately, not
treated as app errors or evidence of good frame rate. An initial responsive
test incorrectly tried to zoom in with the disabled level-bar button; it was
corrected to use the application's country/city selection flow.

Current trees remain too large in some locations and obscure parts of compact
buildings. Their redraw, palette/scale benchmark, crown masks, clustered
placement and spatial-bucket budget are the next accepted slice in
[the implementation plan](COMPACT-WORLD-NEXT-DELIVERY.md). This is deliberately
not claimed as finished. The existing generic silhouette warning for the clinic
and fire station remains advisory; neither is a newly generated park asset.

Not repeated in this slice: full touch/Safari/PWA lifecycle, push delivery,
traffic/aircraft endurance, every requested service family, production-scale
database load, coordinated deployment and rollback. An independent read-only
review of the allocator and public-space integration found no confirmed blocker;
it does not replace those remaining gates.
