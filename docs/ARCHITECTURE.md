# Архитектура и сущности

Tasktopia: React/PixiJS → изолированные Fastify runtime (`web`, `mcp`, `world`) → доменный `AppService` → раздельные асинхронные пулы PostgreSQL 16. Геометрия мира хранится отдельно от read model чанков; terrain вычисляется детерминированно по seed прямо в браузере.

Регистрация вызывает единый `AppService.onboardUser`: аккаунт, session, страна и необязательный первый город создаются внутри одной транзакции. HTTP-route только валидирует вход и не собирает доменный workflow самостоятельно. В production публичный route и UI закрыты по умолчанию через `REGISTRATION_ENABLED=false`; локальная `user:create` CLI использует тот же onboarding workflow, удаляет ненужную CLI-session и остаётся доступной оператору контейнера. Вложенные мутации откладывают realtime-публикацию и cache invalidation до commit внешней транзакции; rollback очищает изменённые in-memory индексы.

## Карта сущностей

| Семейство | Сущности | Владелец и граница | Жизненный цикл |
| --- | --- | --- | --- |
| Identity | `users`, `sessions` | пользователь; session хранится только как SHA-256 hash | controlled CLI/public register → login → restore → expire/logout/delete |
| Access | `countries`, `country_members` | глава `OWNER`, министр `MEMBER`, наблюдатель `VIEWER`; все чтения мира ограничены выбранной страной | create → invite/select → revoke member → delete country |
| MCP | `mcp_tokens` | персональный token; права = текущая роль ∩ scopes, новые expiry 30/90/365 дней | issue → use/last-used → reissue/revoke/expire |
| Country context | поля `countries` | страна выбранного аккаунта | описание, цель, продуктовый контекст, критерии успеха и ограничения обновляются независимо от геометрии |
| State Archive | `country_archives_v1`, `country_archive_records_v1` | singleton страны | короткие устойчивые записи; стадия 1–4 выводится из количества, комплекс на карте не входит в статистику городов |
| City | `cities_v3` | `country_id` | create active → расширение bounds районами; хранит описание, цель, критерии приёмки и deadline |
| District | `districts_v3` | город выбранной страны | planned → active → completed; один active на город; хранит описание и deadline |
| Task | `tasks_v3` | район и город одной страны | planning → started → in-progress → testing → completed; тип работы и AI-поля не меняют жизненный цикл |
| Defect | `task_defects_v18` | дочерний объект задачи | `OPEN → IN_PROGRESS → VERIFYING → FIXED`; хранит шаги, фактический и ожидаемый результат |
| History | `task_comments_v3`, `task_events_v7` | задача; actor может ссылаться на пользователя | append-only; удаляется каскадом только вместе с задачей |
| World | `roads_v3`, `world_features_v6` | страна; feature может принадлежать городу, району и родительской area | создаются/расширяются генератором; районные и дочерние features удаляются каскадом |
| Spatial read model | `world_chunk_entities_v11`, `world_chunk_district_cells_v1` | страна + chunk + entity kind/id; районные клетки ограничены 4096 на строку | trigger insert/update/delete и одноразовый backfill |
| Published chunk payload | `world_chunk_payloads_v1` | страна + chunk + LOD; одноразовая проекция, не источник истины; максимум 2048 на страну | build on miss → content-hash publish → transactional invalidation/retention |
| Generation job | `world_generation_jobs_v1` | страна + operation + idempotency key; PostgreSQL остаётся владельцем очереди | pending → running с heartbeat/lease → completed или bounded retry → failed |
| Integration log | `idempotency`, `events` | страна | mutation+event+response фиксируются одной транзакцией |
| Legacy | `projects`, `sprints`, `tasks`, `task_comments`, `roads` | старая hex-модель | runtime не читает; таблицы сохранены для недеструктивной совместимости/экспорта |

## Инварианты

- Transport не принимает `countryId` как доверенную границу мира: HTTP использует session active country, а MCP требует явный `countryId` и на каждом tool call сверяет его с актуальным `country_members` и ролью владельца персонального token. MCP не читает и не изменяет web active country.
- Чужие city/district/task id возвращают `404`/`403` без геометрии или данных другой страны.
- Изменяющие MCP-команды требуют `idempotencyKey`; запись домена, `worldVersion`, event и сохранённый ответ коммитятся атомарно. Тип задачи (`TASK`, `BUG`, `RELEASE`, `HOTFIX`) не заменяет связанный дефект: дефект всегда остаётся отдельной проверяемой сущностью. Его ремонт не откатывает родительскую задачу из `TESTING`, а переход задачи в `COMPLETED` блокируется до исправления всех связанных дефектов.
- `/mcp` обслуживается официальным web-standard MCP v2 server handler через streaming Fetch→Fastify bridge: основной протокол `2026-07-28`, stateless fallback `2025-11-25`. Аутентификация принимает только персональный `Authorization: Bearer ttp_mcp_...`; Origin проверяется для всех transport methods. Отдельный Hono/Node adapter не используется, поэтому runtime не зависит от несовместимого framework major override.
- Районы четырёхсвязны, не пересекаются и находятся внутри актуальных city bounds. Footprint задач не пересекаются с дорогой, водой и друг другом; вход имеет короткий путь к пешеходной сети.
- `NEW_BUILD` и `PRIVATE` используют квартальные шаблоны; полный видимый asphalt (дороги, asphalt platforms и driveways) не превышает 20% района.
- `world_chunk_entities_v11` использует математический floor и корректно индексирует отрицательные координаты. Geometry UPDATE и DELETE удаляют старое membership.

## Чтение и производительность карты

Один `GET /api/world/viewport` выполняет один country/version read, одну batch-проверку опубликованных payload и один ограниченный пространственный снимок для всех отсутствующих чанков. Построение ограничено четырьмя параллельными chunk-задачами, публикация выполняется одним JSONB UPSERT и одним retention pass. Seeded terrain рисуется до HTTP; полученный payload материализует только инфраструктурный overlay и не заменяет уже готовую природную текстуру.

Создание города, района, задачи и полный replay принимаются web/MCP runtime как идемпотентные команды в `world_generation_jobs_v1`; геометрию исполняет только `world` runtime. Единственное исключение — первый город публичного onboarding: account, country, session и initial city создаются одним синхронным bootstrap-commit, потому что worker не может получить job из ещё не зафиксированной registration-транзакции. Совместимый bounded wait возвращает обычный DTO, если операция успела завершиться. По истечении `GENERATION_WAIT_MS` HTTP возвращает `202 {status:"accepted",job}`, а MCP — успешный accepted-result; состояние доступно через `GET /api/world-generation-jobs/:jobId` и `world_generation.get`. Worker обновляет lease во время длинной транзакции, поэтому второй процесс не подхватывает живую команду.

Планирование города, района и задачи загружает один command-scoped spatial snapshot. Для района/задачи он ограничен изменяемым городом; для нового города — конечным union существующих/new city bounds с коридорным запасом, охватывающим национальный road graph и rural civic sites. Поиск кандидатов, повторные A*, публикация улиц, gateway/архив, тротуары и парк переиспользуют этот снимок вместо повторных country-wide JSON reads. Канонические road cells остаются в PostgreSQL для масок, перекрёстков и traffic graph; транспорт и wire используют compact runs, а новые дороги записываются set-based JSONB batch.

Природный микро-декор и интерьер `PARK/GROVE` — seed-derived presentation data. В PostgreSQL нет отдельных координат для этих props; durable feature описывает только семантическую AREA. `PARK_DECOR` запрещён ограничением БД. Поля `40–52 × 28–38` клеток и их рядки рисуются непосредственно в seed ground texture, поэтому backend не публикует тысячи crop-entities. Кусты и камни остаются редкими связанными macro-пятнами. Все правила используют глобальные world coordinates, поэтому соседние чанки совпадают без общего запроса и cache invalidation.

Дорожная write model остаётся поклеточной ради транзакционных mask/A*/audit, но наружу публикуется компактными `roadRuns`; surfaces и районные клетки используют тот же run-контракт. Профиль `LOCAL=3`, остальные классы `=7` выводится из centerline единым `road-profile` модулем и одинаков для генератора, renderer и directed traffic graph. Переход к каноническим segment rows допустим только отдельной additive-миграцией после cell-for-cell parity; текущий релиз уже убирает поклеточную геометрию из wire, не создавая второй источник истины.

Redis необязателен. При `REDIS_URL` он хранит versioned locator и immutable content-addressed chunk blob, а короткий `SET NX PX` lease объединяет холодную сборку между replicas. Lease-owner сначала проходит PostgreSQL publication/version fence и только затем публикует blob; loser повторно проверяет identity/version, а перед HTTP-ответом выполняется canonical world-version fence. Любая ошибка, таймаут, повреждённый locator или eviction означает cache miss и fallback на PostgreSQL; запуск без Redis имеет тот же контракт и корректность.

Миграция compact district runs выполняется additive-first: `cell_runs_json` backfill и dual-write добавляются без удаления legacy `world_chunk_entities_v11/DISTRICT`. Runtime читает runs и откатывается к `cells_json` для неполной строки. Удалять legacy projection разрешено только отдельной будущей cleanup-миграцией после production parity-аудита.

`/api/bootstrap` отдаёт только identity, выбранную страну, сводку Государственного архива, первый город, общие bounds, counters, `eventCursor` и `worldManifest` (`terrainSeed`, generator/asset revision, chunk size, world revision). `eventCursor` равен максимальному durable `events.id`, уже отражённому в bootstrap; reconnect запрашивает только события с большим id и дедуплицирует повторную доставку. Тот же компактный manifest доступен отдельно в `/api/world-manifest`. План отдельно загружает записи архива и города стабильными cursor-страницами `/api/plan/cities-page` по `(created_at, id)`, затем районы выбранного города, затем задачи выбранного района. Старый массив `/api/plan/cities` сохранён для совместимости. Серверная геометрия приходит только из `/api/chunks/:x/:y?lod=overview|detail`.

HTTP `/api/chunks` по `Accept: application/vnd.tasktopia.chunk-payload+json; version=2` возвращает `ChunkPayloadDto`: дороги, поверхности, обрезанные районы/задачи, features, seed и минимальный контекст декора. Без этого заголовка endpoint временно отдаёт полный `ChunkDto`, чтобы вкладки предыдущего релиза пережили rolling deploy; новый клиент также принимает полный ответ при rollback на старый сервер. Представления имеют разные ETag и `Vary: Accept`. В compact v2 массивы terrain (4096 detail или 256 overview samples) и decorations по сети не передаются; до двух постоянных браузерных Worker'ов детерминированно восстанавливают их из общего pure TypeScript generator. У каждого Worker не больше одной активной CPU-задачи; aborted queued job удаляется, а aborted active job завершает Worker, поэтому новый центральный чанк не стоит за очередью устаревших поколений. Упавший Worker заменяется с ограниченным backoff; после исчерпания попыток один bounded inline executor последовательно дренирует ту же очередь, не создавая параллельный main-thread шторм. Опубликованный JSONB payload хранится в PostgreSQL отдельно от канонических сущностей и переживает рестарт приложения. Запись сериализуется с мутациями через row lock, а удаление устаревших проекций входит в ту же транзакцию, что `worldVersion` и event. L1 process cache при смене версии сверяет content hash с общей PostgreSQL-проекцией, поэтому mutation в другом replica не возвращает stale body. Слабый ETag содержит country и content hash, причём publication/world version исключена из hash projection: визуально неизменный rebuilt chunk сохраняет валидатор после несвязанного события. Актуальный `worldVersion` передаётся независимо в `X-World-Version`, включая 304, и накладывается на cached body до materialization. GPU LRU удерживает до 96 неактивных/недавно видимых ground-текстур, но никогда не вытесняет текущий viewport: на ultra-wide экране эффективный предел равен числу видимых чанков.

Клиент запрашивает только пересекающие viewport чанки; недавно пересечённые границы сглаживает resident LRU без сетевого prefetch-кольца. Сразу после bootstrap отдельный seed-worker строит временный terrain-only ground без HTTP и без decorations; запрос authoritative overlay начинается параллельно и атомарно заменяет этот ground после прихода дорог, тротуаров, районов и объектов. Seed-worker отделён от двух overlay-worker'ов, поэтому большой viewport не ставит серверные ответы за очередью фонового рельефа. Центральный план проходит ограниченные очереди `fetch → worker materialize → ground assets → queued bake → paint → entity assets` по одному чанку: медленный фон, фасад или prop не создают viewport-wide барьер. До восьми payload читаются и до шести наборов ассетов готовятся параллельно; ambient-набор не блокирует ground. Compact payload LRU хранит до 160 ответов, decoded LRU — до 48, detail локально даёт overview. GPU ground LRU имеет базовый предел 96 и повышает его только до числа текущих видимых чанков; лимит применяется при каждом texture install, включая незавершённые и отменённые поколения. Terrain, surfaces и roads одного чанка сначала собираются во временном контейнере, затем не чаще одного раза за animation frame запекаются в RenderTexture и представлены одним Sprite: detail использует resolution 1, а уже укрупнённый overview — resolution 0,5, сокращая его GPU-память и raster work примерно в четыре раза. LOD-ground готовится по одному чанку за frame, а устанавливается атомарно до dynamic entities. Entity payload публикуется в reconcile-набор только после загрузки его ассетов, поэтому соседний reconcile не может навсегда создать `Texture.EMPTY`. Обычный status event загружает нужный stage asset и патчит задачу напрямую; переход через stage 3 дополнительно патчит соседний decoration context и повторно материализует entities локально, не запрашивая HTTP и не пересобирая ground. Bounded-карта последних status/progress/stage накладывается до и после каждого Worker, закрывая гонку с уже летевшим старым payload. AbortSignal проходит до materializer, а decoded LRU принимает результат только от всё ещё актуального pending request. Metadata/defect events перечитывают entity payload, но не пересобирают static ground. Decoration context несёт одноклеточный district ownership halo и компактные соседние access paths, поэтому seam не становится ложной границей забора, а frontage decor не перекрывает подход соседней задачи.

Клиент собирает bounded rolling-window telemetry (128 последних samples) для decoded payload bytes, request+body latency, JSON parse, worker materialization и GPU ground bake. На `.world-canvas` публикуются `last/max/p50/p95/p99`; размер берётся из уже прочитанного HTTP body без повторного `JSON.stringify` большого payload на main thread. Транспорт публикует отдельный контракт `data-vehicle-animation-frames="4"`; motion phase вычисляется чистой функцией из пройденной дистанции и не требует дополнительных PNG или объектов Pixi.

Pixi canvas живёт весь срок выбранной страны. До первого готового ground поверх canvas остаётся явный loader; последующие чтения показывают компактный неблокирующий индикатор поверх сохранённого кадра, а базовый фон предотвращает открытие пустой области при быстром панорамировании. Общий `entity-reconciler` обновляет entity-слои по id/signature: неизменённые здания, районы, декор и world features не уничтожаются при панорамировании или единичном status event. Движущиеся агенты также reconcile-ятся по стабильному session ID и сохраняют позицию/маршрут между загрузками чанков; overview только скрывает слой. Один bounded BFS строит маршрут на его границе, а не каждый animation frame. Чистый `planVehicleFrame` сравнивает короткие пути ограниченного резидентного потока (не больше 24 машин и 4 автобусов): учитывает реальные габариты спрайтов, сохраняет интервал за лидером и заранее резервирует конфликтную клетку до полного выхода хвоста, не меняя граф и не создавая render state. Самолёт расположен в отдельном world-space слое над остальными сущностями: движение камеры одинаково преобразует самолёт и землю, а ограниченный двенадцатью элементами след не накапливает графику.

Перегенерация страны использует transactional shadow build: временная страна изолирует полный повторный запуск production-генератора, после чего геометрия копируется в существующие semantic rows. Это сохраняет внешние ID и append-only историю и исключает публикацию частично перестроенного мира.

Перед публикацией локального road profile генератор проверяет ownership всех новых клеток и два сухопутных портала каждого мостового компонента. Highway/fallback anchors ограничиваются независимыми spatial-бюджетами, чтобы большая межгородская сеть не вытеснила локальные точки входа. Workload-норма парков является частью audit и транзакции: отсутствие допустимой зелёной зоны отменяет мутацию, а не оставляет семантически неполный район.

## Realtime и отзыв доступа

Socket.IO живёт только в `web` runtime, проверяет HttpOnly session на handshake и помещает соединение только в комнату выбранной страны. Каждую минуту long-lived соединение повторно проверяет session и active country. `mcp` и `world` публикуют после commit только bounded id уже сохранённой строки `events` через PostgreSQL `NOTIFY`; `web` читает каноническое событие и доставляет его в нужную комнату. Событие несёт `affectedBounds`; клиент перечитывает только пересекающиеся resident chunks и игнорирует событие другой страны. Удаление участника из правительства отключает его соединения этой страны, logout отключает все сокеты session user.

## Миграции и эксплуатационные границы

Версионные SQL-миграции применяются до старта HTTP под PostgreSQL advisory lock; имя и SHA-256 фиксируются в `schema_migrations`, изменение уже применённого файла останавливает запуск. Каноническая JSON-геометрия пока сохраняется для совместимости, но chunk-read районов читает `world_chunk_district_cells_v1`: одна строка содержит клетки ровно одного `64×64` чанка и не может превышать 4096 элементов. Проекция и membership поддерживаются триггерами insert/update/delete. Одноразовый CLI читает legacy SQLite только в read-only режиме, импортирует dependency-ordered batches в пустую PostgreSQL-схему и сверяет counts/constraints; исходный файл не удаляется. Production запускает web API/Socket.IO, MCP и полный world replay отдельными процессами с пулами 10/4/4 соединения; CPU-stall одного Node event loop не останавливает healthcheck и карту другого процесса. Все процессы пока используют один PostgreSQL, поэтому длительная блокировка той же строки страны остаётся общей транзакционной границей.
