# Проверка доступа к стране — 29 сентября 2026

В паспорте страны глава открывает форму «Пригласить участника», вводит email существующего аккаунта и выбирает «Министр» или «Наблюдатель». Доступ предоставляется сразу, письмо не отправляется. Отзыв доступа требует подтверждения и сохраняет задачи/историю. Управление доступом отделено от изменения работы через MCP.

| Сценарий | Результат |
| --- | --- |
| Пригласить зарегистрированного пользователя | Восстановлено в паспорте; список обновляется без перезагрузки карты |
| Выбрать полномочия | Министр / Наблюдатель при добавлении; OWNER не принимается сервером |
| Неизвестный email / повторное добавление | Понятная ошибка, форма сохраняется |
| Отозвать доступ / отменить отзыв | Подтверждение; после удаления API страны возвращает участнику 403 |
| Защитить главу страны | Нет кнопки удаления; сервер не удаляет OWNER |
| Министр и наблюдатель | Видят состав; элементы управления скрыты; сервер проверяет права независимо от UI |
| Ошибка загрузки правительства | Сообщение и повтор; управление недоступно до получения списка |
| Мобильный экран | Форма и подтверждение помещаются в 390 px |
| Вход / регистрация | Пройдены существующие browser regression, включая дубликаты, пароли и повтор отправки |
| Профиль / выход / MCP | Существующий интеграционный browser journey прошёл: раздел профиля, создание/копирование/отзыв ключа, выход |
| Задачи, документы, города | Остались только для просмотра и навигации; автоматических рабочих записей при просмотре нет |

## Границы текущего продукта

- Приглашения незарегистрированных пользователей по письму отсутствуют. Сначала нужен аккаунт на том же сервере. При выключенной публичной регистрации аккаунт создаёт администратор существующим CLI.
- Самостоятельной смены/восстановления пароля в текущем UI/API нет. Это отдельный пробел жизненного цикла аккаунта; не считать его проверенным или реализованным.
- Редактирования роли существующего участника отдельной командой нет. В этом исправлении восстановлены существующие операции добавления и отзыва, новые административные API не добавлялись.
- Это проверка основных пользовательских сценариев, а не заявление о полном покрытии всех функций проекта.

Изменение UI не требует миграций и перегенерации городов. Проверки выполнялись локально на тестовой БД; реальные участники и доступы сервера не менялись. Для публикации нужен обычный согласованный выпуск.
