# Участки, переносы и изоляция городов

Подтверждено пользователем: сначала tasktopia.online, Letsto/Kubernetes не меняется.

## Результат

Задача не задаёт размер или семейство здания. Сначала выбирается свободный участок текущего района во всех его кварталах, затем подходящее оформление. Оценка работы сохраняется как рабочий показатель, но не определяет размеры. Перенос через MCP освобождает исходную землю и сохраняет номер, бизнес-поля и историю. Старые MOVE становятся архивными записями, не препятствующими застройке. UI только для просмотра и навигации.

Городская сцена изолирована по cityId до подготовки дорог, поверхностей и декораций; общий terrain и необходимые межгородские дороги остаются. Застройка не вторгается в другие города. Перегенерация заменяет производную геометрию транзакционно, без потери задач и истории. Структурные ограничения инфраструктуры (порт/вокзал/аэропорт) сохраняются.

## Последовательность и доказательства

- [x] Изолировать сцену: соседние города в одном чанке не отдают друг другу задачи, MOVE, участки, тротуары и внутренние дороги; регрессия сервиса + браузер.
- [x] Заполнение всех подходящих участков: убрать latestBlock; стабильность размещений, детерминизм, отсутствие перекрытий, инфраструктурные исключения.
- [x] Создание через MCP без геометрических параметров: контракт отклоняет устаревшие поля; семейство выбирается после участка; обновить руководства.
- [x] Перенос освобождает исходный участок: атомарность, повторный ключ, конкурентный доступ, аудит; старые MOVE архивируются миграцией без удаления истории.
- [x] Проверить границы и перегенерацию: копия данных, сравнение бизнес-данных до/после, аудит геометрии, повторяемость и откат.
- [x] Карта/UI: подготовленные миниатюры, компактный loader, непрозрачный terrain; проверить города, районы, задачу/PWA, панели, уведомления, документы и авторизацию на desktop/mobile. Не добавлять управление задачами в UI.
- [ ] Итоговые проверки, AI-ревью, SCM, managed dev release, резервная копия и перегенерация tasktopia.online, проверка SHA/здоровья/сохранности.

## Риски и восстановление

Нельзя просто удалить MOVE: история защищена триггером. Миграция отделяет историю от занятости. Новая схема и логика выкладываются одним согласованным релизом; откат данных — восстановление проверенной резервной копии, а не только старого приложения. Нельзя переиспользовать кэш общего чанка для сцены одного города. Перегенерация не делает внешних вызовов или побочных действий за пределами транзакции. При нарушении аудита не публиковать новую геометрию.

## Проверка кандидата

Общий прогон: 1407 тестов, 1357 прошли сразу. 50 отказов разобраны: 41 относился к отсутствовавшим локальным Python/tmp prerequisites, остальные — к изменённому контракту MOVE, выбору участка, списку миграций и старому test spy. Повтор затронутых файлов: 106 успешных тестов; два оставшихся исправления проверены отдельно (13 успешных тестов). Непрохождений не осталось. Новый UI руин: 4 теста. Conservation release helper: 5 тестов Python.

Браузер: 27 сценариев авторизации, документов, панелей, границы травы и task/PWA entry; отдельно перенос/освобождение участка/удаление/повторный вход и фоновые инциденты. Ранние отказы отдельного fixture исправлены: выбирается открытый район; после перезагрузки тест входит в город с планеты.

Копия tasktopia.online: восстановление PostgreSQL 16; 10 стран, 12 городов, 352 задачи. FORCE-перегенерация и аудит завершились без нарушений. Полный maintenance-conservation сохранил 22 881 запись 33 таблиц. Дополнительная проверка 12 городских сцен сверила точные наборы задач и принадлежность объектов; подготовка сцены локально 10–58 мс, кэш 1–5 мс. Эти числа измеряют серверную подготовку, не сетевую загрузку браузера.

UI и протокол: удалён путь MOVE → текущая задача; руины остаются доступными для просмотра. Внутренние инструменты подготовки художественных fixtures сохраняют явные параметры, но публичный MCP их отклоняет без адаптера совместимости. Исторические записи БД не удаляются.

## Выпуск и откат

Использовать `dev-server`, managed manifest и `update-server.sh compact-cutover prepare/accept` без `--preserve-world`: frozen backup, независимое восстановление, FORCE-перегенерация, полный conservation и аудит до возврата трафика. При ошибке — `compact-cutover recover` того же run-id до accept. Letsto не изменяется.
