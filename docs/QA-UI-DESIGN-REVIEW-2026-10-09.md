# Дизайн-ревью и проверка интерфейса — 09.10.2026

Проверены страницы, панели, модальные окна и основные пользовательские действия Tasktopia. Исправлены обнаруженные проблемы поиска, ожидания загрузки, закрытия окон, блокировки фона, клавиатурного фокуса и размещения содержимого на маленьком экране. Сохранён утверждённый стиль «хвойный атлас».

База: `d872ab4b1abd9123964ae64da1e44efb55047af1`. Работа локальная, ветка `codex/city-everyday-events`; публичный сайт в этой проверке не обновлялся. Данные проверок находятся в отдельной схеме `ui_design_*` локальной `tasktopia_test`. Исходный checkout, другие серверы и существующие превью спрайтов не изменены.

## Метод и критерии

Применены дизайнерские навыки [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) и [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines), включая [актуальные рекомендации по интерфейсам](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md). Их рекомендации сопоставлены с существующей палитрой, компонентами и [продуктовыми правилами](PRODUCT-UI-RULES.md). Новая эстетика поверх согласованной темы не вводилась.

Проверка состоит из чтения исходников, реальных браузерных действий, инъекций задержек/503, проверки DOM-геометрии и ARIA, axe и просмотра фактических скриншотов. Подробная карта 41 исходного TSX-владельца, маршрутов, токенов и общих контролов находится в [дизайн-документе](design/FOREST-ATLAS-REDESIGN-2026-10-08.md); добавлен общий владелец `UiLoadState`.

Критерии приёмки:

- Вход, карта, документы, настройки, паспорт, архив и карточки сохраняют общие цвета, типографику, радиусы и интервалы.
- Открытие показывает понятное ожидание; ошибку можно закрыть или повторить; поздний ответ не открывает закрытое окно.
- Модальное окно блокирует фон, удерживает Tab, закрывает только свой слой по Escape и возвращает фокус в существующий контекст.
- Задачи открываются из поиска, документов, района, здания, развития, уведомлений и прямой ссылки.
- Основные контролы доступны на 320/390/768/1440 px, в горизонтальной ориентации, с увеличенным текстом и уменьшением движения.
- Нет новых рабочих кнопок изменения задач, городов, районов или архива; нет дополнительных чтений сцены при обычном открытии города.

## Найдено и исправлено

| Дефект | Исправление / проверка |
| --- | --- |
| При поиске старый результат оставался доступен до следующего ответа; ошибка выглядела как отсутствие задач | Немедленная очистка/инвалидация запроса, loading/error/retry, AbortController и защита от поздних ответов. Стрелки выбирают нужный результат, Enter не открывает прежнюю строку |
| Некоторые lazy-окна не показывали загрузку или оставляли непонятный глобальный loader | Общие закрываемые `DialogLoadState` / `PanelLoadState`, роли status/alert, доступная кнопка закрытия |
| Отказ загрузки JS мог разрушить интерфейс | `UiLoadBoundary` оставляет рабочую карту и закрываемую ошибку. Кнопка восстановления проверена реальным кликом в трёх движках |
| WebKit сохранял неуспешный modulepreload после обычного reload | Восстановление обновляет preloaded JS с нулевым размером ресурса через `fetch(cache: reload)`, читает ответ и перезагружает приложение; timeout 5 s и disabled/pending. Запросы возникают только при явном восстановлении. Без Timing-Allow-Origin успешный CDN-ресурс также может показывать нулевой размер и повторно читаться в этом редком пути |
| Фон оставался интерактивным; Escape/клик мог закрыть список вместе с карточкой | Общий менеджер фокуса и `inert` со стеком/восстановлением прежнего состояния. Список района/архива и документы сохраняют контекст; закрывается верхний слой |
| Фокус терялся после меню или вложенной карточки, особенно в Safari | Стабильный trigger перед открытием, сохранение строки документов, восстановление фокуса после закрытия |
| Архив не позволял повторить 503 в текущем окне | Повтор запроса, status/alert, abort и проверка позднего ответа |
| На 740×320 px и 200% тексте список документов сжимался до непригодной высоты | Прокрутка всей панели с закреплённым заголовком; строка задачи остаётся доступна для открытия |
| Длинное название вытесняло тело карточки; текст почти заходил под close на 320 px | Прокручиваемый заголовок с ограничением 35%, доступный с клавиатуры; отдельный безопасный отступ 68/60 px. Regression проверяет место для содержимого и геометрию относительно close |
| Loader сливался с поверхностью; были повторные подписи и неподходящая подсказка сохранения | Акцентный квадрат loader; убраны дубли документов/настроек/исполнителя и совет сохранять рабочие изменения перед PWA reload |

Дефекты воспроизведены до правок и закрыты проверками. Ошибки подготовки QA отделены: после `vite build` повторно синхронизируются ассеты; тест Firefox запрашивает fixture JSON без zstd; жесты карты остаются в пределах мобильного viewport; сохранённый архивный drawer закрывается явно перед переходом к карте. Проверки продукта не ослаблены ради этих исправлений.

## Проверки и производительность

Итоговый реестр результатов и SHA-256 входов: [summary.json](evidence/ui-design-review-2026-10-09/summary.json). Приведённые там сценарии считаются один раз по `project + file + title`; повторные успешные проверки не увеличивают итог. Незатронутые успешные результаты переиспользованы. Для изменённого общего менеджера окон выполнены проверки всех основных поверхностей, вложенных карточек и клавиатуры.

Завершены **109 браузерных сценариев без оставшихся падений**: Chromium — 57, Firefox — 12, desktop WebKit — 38, touch Pixel 7/iPhone 13 — по одному полному пользовательскому маршруту. Пять пропусков намеренные: desktop-вариант touch в трёх проектах заменён специальными touch-контекстами; два прежних WebKit-сценария ограничены Chromium (CDP safe area и отдельный палитровый тест). Геометрия и axe в WebKit проверены матрицей поверхностей.

Типизация, ESLint, production build и `git diff --check` проходят. Затронутые unit-тесты: 6 файлов / 49 тестов (`task-detail-cache`, `task-share-preview`, `pwa-update`, `pwa-contract`, `api-client`, `world-preferences`). Браузерные результаты и конкретные времена записаны в реестре.

Городская fixture содержит около 40 задач, 3 района, записи архива и руины. Замер `forest-ui-load`: холодное открытие 1597 ms, повторные 94/87/78 ms; один GET сцены без дополнительных chunk/viewport-чтений, отсутствие page errors и 39 336 B двух локальных WOFF2. Геометрические исправления не добавляют фильтры размытия или работу в render loop. Отдельно измерено тёплое открытие карточки физическим кликом по зданию на 320/1440 px: Chromium 47/140 ms, Firefox 43/50 ms, WebKit 43/50 ms, при бюджете <1500 ms. Это локальные измерения, а не обещание такой же задержки на любом устройстве или сети.

Нагрузка города с 200 задачами и полный MCP ранее проверены на базе этой работы: [QA-CITY-200-LOADING](QA-CITY-200-LOADING-2026-10-09.md), [QA-MCP-AUDIT](QA-MCP-AUDIT-2026-10-09.md). Backend, MCP, генерация и спрайты здесь не изменены; эти проверки не объявляются выполненными заново.

## Как повторить человеку

1. Открыть локальную QA-сборку. Проверить вход и меню на компьютере и телефоне, пройти настройки, паспорт и архив.
2. Найти задачу по номеру и названию. Выбрать второй результат стрелками/Enter; закрыть Escape. При задержке не должно быть старых кликабельных результатов, при 503 должен появиться повтор.
3. Открыть задачу из района, документов, здания, развития и уведомления. Нажать Tab/Shift+Tab, перейти по четырём вкладкам, открыть/закрыть превью и карточку. Фон заблокирован только на время модального окна; документы/район возвращаются в прежнем состоянии.
4. Проверить длинное название, код и таблицу на 320 px. На горизонтальном экране и с увеличенным текстом закрытие, вкладки и содержимое должны оставаться доступны прокруткой.
5. Ограничить скорость сети, открыть документы/настройки и закрыть до загрузки. Позднее окно не появляется. Для отказа lazy JS доступен error с восстановлением; после возврата сети кнопка открывает рабочий интерфейс.
6. Создать только локальное публичное превью, открыть в гостевом окне, проверить изображение/CTA; отозвать и проверить понятную страницу 404.

Пример запуска после сборки и подготовки **отдельной локальной схемы**:

```sh
node dist/synchronize-assets.mjs
E2E_BASE_URL=http://127.0.0.1:5230 E2E_SEED_COMMAND=true E2E_FOREST_UI_FIXTURE=true \
  npx playwright test tests/e2e/ui-design-review.spec.ts tests/e2e/ui-public-preview.spec.ts \
  --project=chromium --project=ui-review-firefox --project=ui-review-webkit --workers=1
```

`E2E_DATABASE_URL` должен быть задан приватно для изолированной схемы. Touch выполняется отдельными проектами `ui-review-mobile-chromium` / `ui-review-mobile-webkit`; четыре ширины — `forest-ui-surfaces` в Chromium/WebKit. Публикация превью, смена пароля, создание ключа и архивная fixture допустимы только в одноразовом QA-окружении.

## Границы

Проверены реальные браузерные движки и touch-контексты Pixel 7/iPhone 13, включая смену ориентации. Физические устройства, системный Safari zoom и установка iOS PWA не проверялись. 200% в этой матрице означает увеличенный корневой размер текста. Axe не заменяет полный аудит WCAG со всеми вспомогательными технологиями.

Длительные симуляции, новые атласы/спрайты, все комбинации графа зависимостей, нагрузка публичного сайта, managed release и SCM approval не входили в локальную UI-приёмку. RepoWise вернул устаревший индекс другой копии; проверка опиралась на прямые исходники. Внешняя Tasktopia читалась с закреплённым `countryId`; рабочие записи и внешние сообщения не менялись.
