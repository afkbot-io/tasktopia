# Воспроизводимость PNG при подготовке RELEASE №14

Статус: исправление сборочного инструмента; production не изменён.
Пользователь подтвердил ревью кандидата `d83674cc42269909f674618ddf0ee45e324a5188`,
включая CDN-исправление. Описанный ниже новый diff в это подтверждение не входит.

## Причина

[CI 34097128549](https://github.com/afkbot-io/tasktopia/actions/runs/34097128549)
останавливался на `assets:build`: 105 стадий имели прежние source SHA и измерения,
но другие SHA закодированных PNG. Локальная авторская среда использовала
Pillow 12.3.0; CI устанавливает закреплённый Pillow 11.3.0. PNG/zlib-кодирование
также различается между платформами. На шести изолированных стадиях проверено
полное совпадение размеров и RGBA; два CI-хеша воспроизведены одной перепаковкой
DEFLATE без изменения пикселей. Это не доказательство совпадения всех Linux PNG.

Дополнительно обнаружены вызовы `get_flattened_data`, отсутствующего в
закреплённом Pillow 11.3.0, в нормализаторе деревьев и двух тестах.
Два отрицательных теста стойки для велосипедов также зависели от локальных
неотслеживаемых `rejected/`-исходников. Их точные копии теперь лежат в
`tests/fixtures/courtyard-art/`, отдельно от игровых assets; утверждения тестов
и исходные пиксели не меняются.

## Контракт исправления

Нормализаторы зданий, парков, деревьев и дворовых объектов по-прежнему вычисляют
новый растр из исходника. Для утверждённого изображения требуется одновременно:

1. SHA исходника совпадает с прежним visual review.
2. Существующий canonical PNG имеет утверждённый файловый SHA.
3. Размеры и все RGBA-байты свежей нормализации точно совпадают с canonical PNG,
   включая RGB прозрачных пикселей.

Только тогда сохраняются исходные утверждённые bytes без повторного кодирования.
Отсутствующий/повреждённый canonical PNG, иные пиксели или исходник приводят к
ошибке, а не к автоматическому «исправлению» review. Черновик без утверждения
по-прежнему можно нормализовать. Геометрические и семантические проверки
остаются обязательными. Допуски, размеры, ракурс, палитра, review JSON и
опубликованные изображения этим изменением не редактируются.
Различие стадий проверяется по fresh RGBA и размерам, а не по сжатию PNG:
одинаковые изображения с разными утверждёнными кодировками не проходят.

## Проверки

Выполняются отдельные регрессии всех четырёх CLI: другое lossless-кодирование,
отсутствующий файл, неподтверждённый файловый SHA, изменённый видимый/невидимый
пиксель, размеры, source SHA и нормализация черновика. Полная Linux-проверка
проводится в отдельной копии Git, чтобы не перезаписать утверждённый рабочий арт.

Зафиксированы 95/95 целевых тестов на macOS с Pillow 12.3.0 и отдельно 95/95
с Pillow 11.3.0; scoped ESLint и независимое ревью прошли. Две регрессии
одинаковых стадий сначала были RED и стали GREEN после исправления сравнения.

Полная Linux/amd64-сборка с Python 3.12, Pillow 11.3.0 и Node 24.20.0,
затем весь `assets:verify` прошли. Исходное падение воспроизведено перед фиксом.
Все 381 runtime PNG имеют прежние размеры и RGBA. Только кодирование
71 процедурного PNG отличается; Linux assetRevision — `4336731d4187a108`,
а утверждённый набор в Git остаётся `750f26edc463160e`. Это не новая отрисовка.

Полный Linux typecheck, запущенный параллельно целевым тестам в локальном
Docker, завершился `137 / Killed`; это не успешная проверка. Остальные результаты
типизации: host typecheck прошёл, повторный последовательный Linux typecheck
прошёл с `NODE_OPTIONS=--max-old-space-size=2048`, но следующий полный Linux
ESLint также завершился `137 / Killed`. Полный `npm run lint` затем прошёл
в чистой host-копии с теми же изменёнными исходниками. Docker доступно 3,827 GiB; ограничения
приложения, правила ESLint и CI не менялись ради прохождения проверки.

Итоговый Linux-набор — **153/153 теста, 7 файлов, exit 0**, включая отрицательные
fixtures, ранее отсутствовавшие в чистом Git. Отдельные ограничения локальной
среды не заменяют обязательный общий CI на опубликованной ревизии.

## Проверка чистого Git в GitHub CI

[CI 34102117539](https://github.com/afkbot-io/tasktopia/actions/runs/34102117539)
на `4b1dce1b2f274f94eb915ec64cbf4c451b69f118` прошёл полную Linux-сборку и
верификацию assets, typecheck и ESLint. Unit-набор: **1138 passed, 1 failed**.
Единственный сбой — `tests/readme.test.ts:41`: показанный в README файл
`screenshots/dense-city-final/city-blocks.png` остался только локально и не попал
в курированный commit. Это не успешный общий CI; последующие шаги были пропущены.

Добавлен ровно этот неизменённый PNG: 1 076 496 bytes, SHA256
`9f9ea73b39890f7ffdec53d3206d0884447f00ccfa8b3d038db665f6ef442da6`.
Он получен обычным browser screenshot из синтетического `Riverside Local`
с 40 задачами; отдельное read-only ревью изображения и метаданных не обнаружило
приватных текстов, email или токенов. Это исторический демоснимок от 5 сентября,
не текущая release acceptance и не скриншот production. Прочие локальные архивы
не публикуются, README и проверяющий его тест не ослабляются.
После добавления файла общий CI должен пройти заново на новом точном commit.
Локально в отдельной курированной копии `npx vitest run tests/readme.test.ts
--no-file-parallelism` воспроизвёл RED (тот же ENOENT); после копирования только
этого PNG тот же тест без изменений дал GREEN: **2/2, exit 0**.

Предыдущие
CDN/браузерные проверки описаны в [отдельном отчёте](QA-CDN-RELEASE-2026-09-07.md)
и не заменяют Linux CI.

## Границы релиза

API, БД, миграции, генерация городов, gameplay и deployment guards не меняются.
Остальные условия выпуска остаются в силе: новый diff требует human review;
нужна чистая актуальная Builder-копия, successful CI, frozen backup/restore,
точная merged revision и `builder release validate` с `ready:true`.
Online-копия production для репетиции не заменяет backup после остановки записи.
