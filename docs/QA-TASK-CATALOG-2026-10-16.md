# Поиск и каталог задач: U03/U05

## Реализовано

Поиск и каталог используют `GET /api/tasks/list-page` с явным countryId,
размером страницы 50 и курсором производителя. В DOM и памяти остаётся
только текущая страница задач. Next/Prev сохраняют только цепочку курсоров;
смена страны, условий или revision начинает новый список с первой страницы.
Ввод поиска ограничен 160 символами. HTTP имеет deadline восемь секунд,
отменяется при уходе; запоздавший ответ не публикуется. Проверяются контекст,
версия, размер страницы, дубликаты id и продвижение курсора.

Каталог сочетает текст/номер, район, статус, тип, приоритет и «Мои задачи».
На карте одновременно выбранные подсветки образуют пересечение; одна ревизия
метаданных переиспользуется до минуты, переключение условий не меняет камеру
или землю. Пустые результаты, отказ, повтор, пагинация и сброс явно отображаются.
Сброс возвращает первую страницу и начало прокрутки условий.

CityDirectory даёт путь города→все районы→задачи, включая завершённые и
заполненные районы. Есть поиск района и список всех задач города. Навигация
с клавиатуры не требует canvas-click. Callback DTO сохраняет реальную
позицию/город задачи; после закрытия карточки доступен прежний каталог.
Полная районная сводка показывается только по доказанно полной первой
странице без условий (не более 50 задач); частичная страница не выдаётся за
весь район. Архив и рабочие объекты остаются только для чтения.

## Проверки

16.10.2026: Vite 5315 с immutable foundation API 5316, изолированный реальный
набор 200 задач, авторизованный синтетический пользователь. Производственные
данные, задачи и геометрия не изменялись. API login пишет лишь тестовую сессию;
проверка отказа каталога перехватывает HTTP с 503. AccountSecurity использует
общий Field: показать/скрыть три пароля проверено без account password POST.

Успешны **25 сценариев** в desktop Chromium/Firefox/WebKit, Pixel Chromium и
iPhone WebKit: поиск после десятого результата, Next/Prev/50 DOM, keyboard
selection/Card, комбинированные условия/empty/reset, каталоги всех районов,
отказ и retry, возврат фокуса, кеш подсветки/камера/земля, пароли аккаунта.
Axe serious/critical нарушений в проверенном каталоге не обнаружено; 320 px
без горизонтальной прокрутки. Native screenshots просмотрены. Это
функциональная QA с Vite, не производственный performance benchmark.

Сохранены и исправлены два наблюдения: exact getByLabel на label с вложенными
option был неверным тестовым locator (заменён accessible combobox role);
возврат исходного filter-key сохранял старую page2 — реальный дефект,
воспроизведён новым assertion и исправлен reset stored scope. Последние
10 search/catalog сценариев повторены во всех пяти профилях: **10 PASS**.
Остальные 15 сценариев переиспользованы с неизменными проверяемыми путями.
Pointerdown внутри портала не закрывает underlying toolbar disclosure.

Focused unit: 8 PASS (reader, combined filter, existing single filter и
metadata loader). ESLint и отдельная strict TS граница прошли; общий
frozen production build, CI, проверка 1000 и релиз — последующие общие этапы.
Физические устройства не проверялись, применяется браузерная эмуляция.

Сценарий: `tests/e2e/task-catalog-navigation.spec.ts`. Сырые логи и снимки:
`.builder/world-perf-20261016/u03-*`. Для данной локальной проверки применён
ignored Playwright config с пятью ui-review profiles; root добавляет файл в
постоянную release matrix. `E2E_CATALOG_FIXTURE_EMAIL` выбирает синтетический
200/1000 аккаунт. На обычной малой fixture два scale сценария явно пропускаются,
если у реального производителя нет второй страницы; для release scale QA
используются ровно 200/1000.
