# Модель угроз управляемой подготовки 1.28.0

Граница: явный opt-in `prepare --preserve-world --prepare-living-city` внутри существующего заблокированного cutover. До новой фазы уже проверены совместная резервная копия/восстановление и полная сохранность строк после миграции. Сама фаза работает при закрытом трафике и остановленных app/mcp/world. На сервере ещё ничего не запускалось.

Активы: задачи и их история, геометрия городов/районов/зданий/локальных дорог, принятые междугородние маршруты, замороженные аэропорты/ЖД/остановки, credentials, точный образ и журнал восстановления.

Контроль оператора ограничен существующим разрешением на релиз: нельзя передать произвольную команду, образ, shell-фрагмент, страну или путь. Идентификаторы стран читает PostgreSQL; допускается только UUID. Три entrypoint заданы константами. Параметры — `--country UUID` и необязательный `--write`. Исполняется тот же digest кандидата с прежними readonly/cap-drop/no-new-privileges/CPU/memory/pids ограничениями. Новые CLI не получают REGENERATION_FORCE.

Угрозы и проверки:

- Подмена фазы при recovery/accept: флаг разрешён только в prepare+preserve-world и входит в binding/targetId. Отсутствующий флаг сохраняет прежнее поведение.
- Незамеченный writer: повторная полная assert_frozen перед каждым CLI и перед итоговым сравнением. Любой сбой запрещает активацию и требует штатного joint recovery.
- CLI выдаёт неверный успех: строгие event/mode/country, конечные целочисленные лимиты, SHA, точный авторитетный набор городов, готовность всех сцен/остановок и физическая неизменность повторного запуска. Preview также сравнивается с состоянием БД.
- Порча данных при успешном CLI: независимо сравниваются все исходные строки/поля, включая геометрию и историю; исключается только world_version страны. Замороженные планы могут только дополняться. Каждый старый принятый road object сохраняется целиком. Производные кэши имеют закрытый перечень.
- Инъекция/утечка: SQL использует фиксированные таблицы и проверенные UUID; shell не участвует. Секретный env и ограниченные логи пишутся только в private run dir. Хеши кэш-строк считаются в PostgreSQL без экспорта blob или содержимого задач в отчёт.
- Зависание/переполнение: общий deadline 1800 секунд, лимиты стран/городов, ограниченные вывод CLI и таймауты. Ошибка лимита завершает фазу закрыто; таймаут не трактуется как успех.

Остаточные ограничения: это доверенные административные entrypoint, не песочница для произвольного кода; digest образа и репозиторий проверяет существующий controller. Исправление старых некорректных frozen-планов не разрешено автоматически: сохранность намеренно блокирует такую выкладку. После открытия трафика и новых рабочих изменений применяется forward fix; до открытия — совместное восстановление БД/файлов/образов по существующему runbook.

Проверка: публичный driver seam, негативные receipt/сохранность/deadline тесты и реальные три compiled CLI на принадлежащей задаче PostgreSQL. Существующие recovery/host CI остаются обязательными.
