# Компактные обновления поверх карты

Быстрая смена стадий одной задачи создавала три большие карточки. На телефоне
они закрывали значительную часть карты. Теперь новая карточка заменяет
предыдущую для той же пары country/task. Очередь ограничена тремя разными
объектами; старые и повторные event IDs не возвращают прежнее состояние.
Удаление заменяет прежнюю ссылку сообщением без перехода к удалённой задаче.

На экранах до600px показывается только последнее уведомление: номер, действие,
открытие и закрытие. Полное название доступно в имени кнопки. Скрытые карточки
не участвуют в фокусе; при закрытии последней может появиться предыдущее
уведомление другого объекта, если его срок ещё не истёк. Desktop сохраняет
полный текст и до трёх карточек. Текущие цвета и шрифт Manrope сохранены.

Таймер удаляет только свой точный event ID. При замене карточки прежний таймер
не сокращает срок новой. Группировка происходит после обработки события:
все domain/replay/cache handlers и долговечные новости остаются прежними.
Текст переноса больше не утверждает, что прежняя площадка сохранена: после
переноса она освобождается по существующему контракту.

Shared presenter содержит два внутренних поля оформления; WebPush по-прежнему
сериализует только title/body/url/tag. API, MCP schema, БД, геометрия и статусы
этим изменением не меняются. Откат — возврат client/presenter, без миграции.

## Проверка

Public RED→GREEN подтверждает группировку, разные страны/задачи, порядок,
неизменность входа, удалённую цель и отсутствие prototype-status. Отдельно
проверяется точный WebPush envelope и канонический URL. Браузерный сценарий
создаёт только собственную локальную страну и меняет её задачи настоящим MCP.
Проверяются три быстрые стадии, три разных объекта, снос, открытие актуальной
карточки с задержанным API, закрытие и реальное семисекундное истечение.

Desktop Chromium, Pixel7 и iPhone13 используют production build; телефонные
viewport явно меньше500px. Проверяются высота≤96px,44px close target, свободные
toolbar/navigation, resize, reduced motion, клавиатура и отсутствие фокуса
у скрытых кнопок. Canvas остаётся тем же, burst стадий читает scene один раз,
дополнительных viewport/chunk GET и UI-записей задач нет. Снимки просмотрены.

Начальные прогоны не засчитаны: тестовый заголовок превышал лимит160 символов;
отдельные запуски остановились на CONNECT_TIMEOUT/подготовке локальной БД.
Дополнительно разделены два разных сценария: структурные MCP-операции могут
длиться больше7s и дать законно истечь предыдущим уведомлениям. Одновременные
три группы проверяются быстрыми MCP-переименованиями. Они по прежнему контракту
обновляют scene, поэтому утверждение об одном GET относится только к burst
стадий. Исправлен только fixture; валидатор продукта, срок карточек и границы
таймера не ослаблены.
Успешные проверки и исходные отказы сохранены раздельно в локальном evidence.

Финальный результат:17 уникальных unit/integration проверок в4файлах и3
browser сценария без retry. Сохранены все6 проверок push delivery, включая
дедупликацию, отозванное членство, terminal410 и legacy URL. Build/typecheck/
scoped lint/diff check проходят. Fixed root AI-review очереди, exact-ID expiry,
доступности и push allowlist не оставил открытых замечаний; это не SCM approval.

Итоговый SCM/release и масштабная приёмка относятся к общей цели живого города.
