## Границы и исходные факты

Каталог исходной версии: 50 инструментов (16 чтений и 34 записи), два ресурса,
промптов нет. Все операции страны требуют явный countryId; записи требуют
idempotencyKey. MCP использует SDK client/server 2.3.0 и stateless HTTP.
Интерфейс приложения остаётся только для чтения и навигации.

Постраничные task.list_page и task.collection_list уже существуют. Найдены
полные чтения layout даже для одной карточки, загрузка всех задач страны в
city.get, отдельные workload-запросы для каждого района, синхронная пересборка
при смене стадии, лишние полные чтения историй. Polling задания проверяет
недостаточный scope и отдаёт входной payload; ошибки worker и ресурсов могут
публиковать внутреннее сообщение. Это выводы по исходному коду; исходная
задержка и улучшения должны быть измерены отдельно.

RepoWise устарел (3161ba52, около 58 дней, текущая ветка не проиндексирована).
Он использован только как ориентир; владельцы и удаления проверяются в исходниках,
импортах, entrypoints, истории Git и тестах. Его оценки не являются доказательством
мёртвого кода или производительности.

Вне работы: редизайн, графика, новая география, игровые механики, изменение
чужих проектов, нагрузка на опубликованный сервер. Старые полные ответы и
совместимые receipts сохраняются; обрезать их молча нельзя. Новые ограниченные
режимы добавляются отдельно и становятся предпочтительными в инструкции MCP.

## Последовательность

1. Сохранить baseline на отдельной локальной PostgreSQL БД. Проверить 10 × 1000
   задач и отдельно предел одного города с 10 000 задачами. Использовать штатный
   компилятор геометрии; не подделывать координаты и capacity guards.
2. Через RED/GREEN сделать точечное чтение геометрии по выбранным task IDs и
   уникальным блокам. Проверить cold/warm, SQL rows/bytes и отсутствие полного
   layout aggregate на compact пути. Индексы добавлять по query plans.
3. Добавить ограниченные метаданные городов/районов/архива и точечное чтение
   записи. Устранить country-wide scan и N+1, сохраняя legacy shape.
4. Исправить scope и sanitization через настоящий MCP SDK, включая исторические
   ошибки задания. Исходный payload фоновой операции не является публичным ответом.
5. Перенести тяжёлые пространственные изменения в существующий durable worker;
   проверить accepted/poll, replay, crash recovery, ошибки, смену scopes и отзывчивость.
6. Удалить только доказанные неиспользуемые private методы/модули/экспорты.
   Включить TypeScript noUnusedLocals/noUnusedParameters и исправить их последствия.
7. Повторить workload, выполнить affected regression и обязательные SCM gates,
   независимое AI review. Обновить руководство MCP и этот контрольный список.
8. Создать PR, выполнить разрешённый merge, закрепить полный resulting SHA.
   Managed-release target dev-server, штатный updater с backup/health/smoke/
   observation. Сверить опубликованную версию, MCP и результаты проверки.

## Доказательства и бюджеты

AC-1: каталог/схемы/initialize, auth/country/scope, resources/jobs, modern/legacy,
timeout/disconnect, безопасные ошибки. AC-2: страницы/фильтры/равные timestamps,
cursor context, документы/коллекции и отсутствие полной геометрии на compact read.
AC-3: фоновые изменения с одним эффектом при повторе и восстановлении.
AC-4: сопоставимые baseline/candidate p50/p95, queries, SQL bytes/rows, payload,
event-loop. AC-5: доказанные удаления и автоматические unused checks.
AC-6: CI, AI review, exact SHA и наблюдение после выкладки.

Workload: warmup и не менее 20 выборок, concurrency 1 и 4, отдельные cold reads.
Страница 50 задач ≤128 KiB; compact command receipt <4 KiB. Целевые p95 локального
чтения ≤500 ms и compact comment ≤750 ms при четырёх клиентах. Цифры — критерии,
а не заявленные результаты. В evidence указывать конкурирующую нагрузку и
разделять InMemory SDK, настоящий HTTP, SQL и генерацию; не выдавать один за другой.

Тестовая БД отдельная, роль отдельная; env в ignored .builder, mode 0600.
Секреты и реальные пользовательские материалы не публикуются. Данные рабочего
сервера не наполняются нагрузочными фикстурами. Миграции добавляют индексы,
расширяют check-ограничения очереди и добавляют nullable TEXT сериализацию;
откат приложения не требует удаления данных. Пользовательский запрос включает
реализацию, merge и выпуск на текущий публичный dev/beta tasktopia.online.
