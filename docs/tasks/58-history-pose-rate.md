# Камера и ограничение History API в Safari

При обычном PLANET/CITY zoom и pan AppNavigation.pose записывал каждый
кадр через history.replaceState. WebKit ограничивает частые записи; в live
iPhone13 emulation получен SecurityError и пустой экран React. Сбой проявился
при проверке обновления дорог через MCP, но canonical route оставался в БД.

Последняя поза теперь сразу доступна в памяти, а запись её кадров объединяется
до5 раз в секунду. Перед явным переходом, открытием или закрытием карточки
отложенная поза сохраняется. Отложенная запись проверяет entryId, URL и место;
она не может перезаписать следующую страницу или другую страну.

Необязательный entryId добавлен к session history version1. Старые записи
без него поддерживаются и получают ID один раз при первом обновлении позы.
Если native Back прерывает ожидающую запись, до20 прерванных поз остаются
в session memory по entryId. Forward восстанавливает свою точную позу,
а не камеру другой записи. После успешного сохранения запись удаляется
из этого кэша. Logout и teardown отменяют timer и очищают весь кэш.
URL, taskDepth, разрешения и рабочие данные не меняются.

Public RED→GREEN:600кадров за9,6с превышали Safari-подобный лимит100записей
за10с. Второй RED показал потерю последней позы при Back до timer. Проверки
после исправления охватывают оба случая, прежнюю history без entryId,
mutable input, чужую entry и отмену сессии.30 unit проверок в5файлах проходят.
На production build пройдены33 браузерных сценария навигации на desktop,
Android и iPhone: Back/Forward, close/Escape, delayed card, logout/login
и повторные PLANET/CITY. Два desktop touch-сценария штатно пропускаются;
их варианты проверены на телефонах. Ещё3 сквозных дорожных сценария с
настоящим MCP, zoom и отказом PNG503 проходят на тех же профилях без retry.
Типы, scoped lint и сборка проходят. AI-review не выявило открытых замечаний.

Это ограничение фоновой записи кадров камеры. Явные переходы страниц
сохраняются сразу и не подменяются отложенным изменением URL.
