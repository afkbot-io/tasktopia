# Память зависимостей геометрии города

Трекер `createCityMovementDependencies` определяет, когда нужно заново
подготовить физику и площадки событий. Он продолжает принимать immutable
снимки и возвращать прежние счётчики `geometry` и `life`.

Вместо JSON-текста с контурами и подходами задачи сохраняются небольшие
массивы скалярных признаков и ссылки на исходную immutable геометрию.
Признаки активности ссылаются на ту же геометрию; повторной строки с её
экранированной копией больше нет. Слабые кэши задач и объектов не удерживают
метаданные старых задач; текущие страницы и таблица активности заменяются.
История снимков не хранится.

Сначала сравниваются ссылки. Новые массивы сравниваются поэлементно,
заменённые объекты — по прежней JSON-эквивалентности, включая порядок
полей. Нормализация элементов массива сохраняет прежние `undefined`/`null`
и `-0`/`0`. Числовых хешей и риска их коллизий нет. Объекты входного DTO
должны оставаться неизменяемыми; прежний WeakMap-кэш имел то же требование.

Название, описание, прогресс и номер публикации не запускают подготовку.
Переход к готовому зданию, вход, контур, завершённость парковки и реальная
геометрия дорог/покрытий продолжают менять `geometry`. Роль службы,
готовность и состояние происшествия меняют `life`. Порядок страниц/задач
и транспортные планы сравниваются по прежним правилам. HTTP/MCP/SQL,
география, арт, физические ограничения и элементы UI не меняются.

## Доказательства и границы

Public RED на128задачах с64клетками: прежний трекер прочитал16384координаты
при создании признаков вместо0. Теперь первоначальное чтение и замена
только метаданных не читают координаты. Независимый сохранённый алгоритм
наa017289d служит oracle для последовательностей замены статусов, ролей,
дефектов, входов, геометрии, объектов, транспорта, порядка и удаления.
Повторное чтение и новые эквивалентные декодированные значения совпадают.

Постоянный GC-тест использует10 000синтетических задач/640 000клеток и
три чередующиеся пары из отдельных процессов, чтобы предыдущая closure
или WeakMap ephemeron не искажали baseline. Данные входа остаются живыми
и исключены из дельты; трекер остаётся живым после GC. Новый расход меньше
8МиБ, экономия больше10МиБ.

На тех же10 000настоящих задачах/459 363клетках выполнены ещё три пары
из отдельных Node24-процессов. Медианы удерживаемой памяти трекера послеGC:
26 302 056→3 397 584байт, экономия22 904 472байта (21,84МиБ).
Входные данные, включая повторные ссылки задач между страницами, одинаковы.
Первый эксперимент в одном процессе дал отрицательные дельты из-за времени
жизни предыдущего замера; он отброшен и не используется как доказательство.

60связанных unit/6files, build/typecheck и scoped lint проходят.
Девять браузерных сценариев обычного города проходят на desktop/Android/
iPhone: реальный автобус, дворовая сцена и авторитетный resync. На настоящем
CITY10000 ещё3сценария проходят по3выхода/возврата: тот же canvas, физика,
площадки и один sceneGET. Повторов runner нет. Тест сначала ограниченно
ожидает обе холодные фазы, затем проверяет сохранение готового города;
он не используется как доказательство быстрого холодного входа.

Один hardwareMetal desktop1440×1000/DPR1 профиль послеGC подтверждает
549,7→526,3МиБ всего main heap. Карта4,48→4,53s, готовность движения
19,90→19,83s; изменение предназначено для памяти, ускорение не заявляется.
В default headless при обычном переходе PLANET→CITY без тестового
наблюдателя получены5,00s до карты и44,14s до полной физики; canonical
projection17,87s и movement21,08s. Ошибок приложения нет, один sceneGET.
Причина различия графического режима/перехода ещё не изолирована;
числа не смешиваются с hardware directCITY и не выданы за пройденный
итоговый performance gate. Отдельные функциональные ожидания30s на каждую
холодную фазу выявляют сохранность/завершение, а не соответствие скорости.

AI-review fixed diff: scalar/array equivalence, immutable input, слабые
кэши/отсутствие истории, scoped lifecycle и новые тесты просмотрены.
Открытых замечаний этого среза нет. Прежние неуспешные cold asserts5s/30s
сохранены в доказательствах; увеличение тестового ожидания не исправляет
медленную начальную подготовку.
Весь город пока удерживает полную физическую сеть и развёрнутые данные;
это изменение не означает достижения256МиБ или окончания всей цели.
Откат — обычный клиентский revert через управляемый выпуск, без миграций.
