# Обновление PWA и восстановление карты

Задача 19, страна `4201d605-751a-469b-8d5f-a7e322a7ece1`.
База: `abfae8120267f6129db27a85d6db17ef1763da98` (1.24.1).

## Результат

- Готовая новая версия показывает компактное уведомление с кнопкой «Обновить».
  До нажатия страница не перезагружается. Предупреждение предлагает сохранить
  введённые изменения; после смены controller выполняется одна перезагрузка.
- Поддержаны уже ожидающий worker, установка во время работы, возвращение
  в приложение, восстановление сети, ошибка активации и обновление другой вкладкой.
  Проверки ограничены частотой: не чаще минуты при возвращении/online,
  каждые 30 минут в открытом видимом приложении.
- Service worker предварительно скачивает entry-граф и CSS; остальные модули
  кэшируются по обращению. Один CDN-файл больше не скачивается также с app-origin.
  В локальной сборке: 6 файлов модулей вместо 38, около 0,49 вместо 1,45 МБ
  без сжатия. Это объём precache, а не измерение скорости пользовательской сети.
- API-тайм-аут страны и ошибка графики различаются. Для обоих доступен повтор
  прямо на карте. Ошибка больше не оставляет бесконечный индикатор подготовки.
- Незавершённые изображения отменяются при тайм-ауте и выходе. Самолёты
  загружаются отдельно от первого кадра и только при существующих маршрутах.
- Кнопка повтора исключена из pointer capture карты.

## Диагностика и границы

В наблюдении после прошлого релиза country overview ответил 200 за 313 мс,
но браузер получил тайм-аут. Точный waterfall той пользовательской загрузки
не сохранён; единственную причину конкретного инцидента установить нельзя.
В коде подтверждены лишний массовый precache и ожидание декоративных самолётов;
воспроизведены тайм-ауты API и изображения с успешным восстановлением.
Сетевой дедлайн 20 секунд сохраняется: бесконечная сеть не объявляется успешной.

Новый UI не может появиться в уже исполняющемся старом JavaScript без его
обновления. После первой выкладки понадобится один раз закрыть старые окна PWA
и снова открыть приложение онлайн. Следующие версии предлагаются кнопкой.
Физическая iOS PWA в этой проверке не использовалась.

## Проверки

- `npm run build`, `npm run lint`.
- `npx vitest run tests/pwa-update.test.ts tests/pwa-contract.test.ts tests/map-image.test.ts tests/map-load-timeout.test.ts tests/map-scene-cache.test.ts`: 39 тестов.
- Две новые worker-регрессии воспроизводятся на исходном файле базы: нет обработчика
  активации, precache загружает lazy-модули и дубликаты. Исправленный файл проходит.
- Chromium и WebKit (профиль iPhone): реальный построенный app и две версии service worker; ввод до
  обновления сохраняется, кнопка переключает controller на версию 2.
- Chromium: API задержан сверх 20 секунд, повтор открывает страну.
- Chromium: изображение воды задержано сверх 20 секунд, повтор открывает страну.
  Этот тест также обнаружил и проверяет исправление конфликта pointer capture.

## Выпуск и откат

Изменения подготовлены к ревью; выкладка в эту задачу не входит. Схема БД,
каталог зданий и генерация не меняются. Откат — клиентский revert и штатный
управляемый выпуск; пересборка пользовательских стран не требуется.

AI-ревью: проверены lifecycle/повтор/границы кэша, ввод и pointer capture.
Блокирующих замечаний не осталось. SCM approval и проверка на физическом iPhone
не заявляются; merge и релиз не выполнялись.
