# Непрерывная земля возле транспорта

Камера CITY может выходить за прямоугольник сцены, чтобы показать станцию или
аэродром. Эти границы навигации не означают, что соответствующая земля уже
присутствует в сцене. Прежняя проверка исключала из локальной дорисовки весь
расширенный прямоугольник; отсутствующие чанки оставались цветом фона Pixi.

Пять потребителей padding и готовности камеры используют фактический набор
ключей `scene.chunks`. Видимая область за его пределами получает прежние
канонические terrain, деревья и дорожные overlays. Навигационные границы,
масштаб, география, серверный контракт и данные города не меняются.
Проверка принадлежности использует переиспользуемый `Set`; работа ограничена
видимым viewport и прежним одним halo, очереди и лимиты сохранены.

## Регрессия

`tests/camera-terrain-padding-coverage.test.ts` проверяет независимый расчёт
экранного пересечения чанков: расширение под ЖД, отрицательные координаты,
фактическое владение страницами и halo 0/1. Дополнительные тесты готовности
камеры и очереди проверяют, что новый кадр не публикуется до готовности земли.

`tests/e2e/city-terrain-coverage.spec.ts` использует локальный демо-город и явно
контролируемый HTTP-вариант транспортной границы. Меняются только координаты
реального железнодорожного коридора и его непрерывного подхода. Bounds,
чанки, задачи и аэропорты сохраняются и проверяются хешем. Это проверка
контракта транспорта за пределами сцены, а не копия личного города со скриншота.

После настоящего drag обязательна непустая видимая область внутри границ
навигации, но вне resident chunks. Проверяются фактические PNG-пиксели этой
области, готовность карты, отсутствие ошибок и один запрос сцены без запросов
viewport/chunks. Desktop дополнительно изменяет высоту окна до 1440×1100;
iPhone WebKit проверяется в браузерной эмуляции.

Проверять следует production-сборку, как в обычном Playwright webServer.
Dev StrictMode намеренно отменяет первые bootstrap/плановые запросы при
повторном mount и создаёт другой сетевой lifecycle. Для этих отмен в
регрессионном сценарии нет исключений; не подменять production-проверку dev.

```sh
npm run test:db:start
npm test -- tests/camera-terrain-padding-coverage.test.ts tests/city-terrain-padding.test.ts tests/world-camera.test.ts tests/city-residency.test.ts tests/city-ground-readiness.test.ts tests/city-camera-presentation.test.ts tests/ground-bake-budget.test.ts tests/padding-retry.test.ts
npm run test:e2e -- tests/e2e/city-terrain-coverage.spec.ts --project=chromium --project=world-review-iphone --workers=1 --retries=0
npm run test:db:stop
```

Тесты работают с отдельной локальной тестовой БД. Исправление не требует
миграции, перегенерации мира или повторного наполнения города 10000 задачами.
