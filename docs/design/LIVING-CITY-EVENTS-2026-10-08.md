## Сценарии и инварианты

Строительство: свежий WebSocket status со сменой стадии захватывает существующий
вид. Бригада приходит к участку, работают инструменты, поднимается пиксельная
пыль. Короткий закрывающий клубок скрывает смену; после него показывается уже
загруженная актуальная стадия. Статус без смены стадии не запускает спектакль.

Снос: отключается выбор удалённого объекта. Бригада готовит условные заряды,
отходит, короткий мультяшный хлопок и пыль закрывают исчезновение. После эффекта
видны только серверные руины. Это игровая постановка без инструкций по взрывчатке.

Перенос: грузовой вертолёт подлетает, тросы поднимают прежний силуэт, перевозит
его к целевому участку и улетает. Новый участок и конечный вид берутся из
подтверждённой сцены. Старая платформа освобождается, фиктивная задача не создаётся.

Дороги: редкие детерминированные сцены ДТП, дорожного ремонта, пожара,
медицинского вызова и патруля. Службы используют micro vehicle family и безопасные
маршруты движения. Закрытые клетки исключаются из новых маршрутов; подъезжающий
транспорт уступает. После события ограничения и все эффекты удаляются.
Это фоновая симуляция, она не создаёт дефекты задач и не меняет данные MCP.

Общие правила:

- Исторические/replayed events, первое открытие и resync не воспроизводят старые
  стройки. Дубликат не повторяет звук и бригаду. Быстрые изменения одной задачи
  сходятся к последней стадии; удаление отменяет ожидаемое строительство.
- Нельзя показывать незагруженную следующую стадию или навсегда удерживать старую.
  Используются существующий asset retry и ограниченная длительность эффекта.
- Глобальные лимиты одновременных сцен, людей, частиц и аудио. Один ticker,
  без бесконечных таймеров/загрузок, без GPU readback и перегенерации дорог.
- Скрытая карта/вкладка не анимируется и не звучит. При возврате просроченный
  эффект завершается. Reduced motion показывает актуальное состояние сразу.
- Звук по умолчанию отключён, включается личной настройкой и жестом пользователя.
  Нет звука до разрешённого AudioContext, при закрытии/скрытии он прекращается.
- Арт: hard alpha, muted palette, integer pixels, native overhead vehicles и
  существующие workers. Новый грузовой helicopter — отдельная AI-authored family
  с четырьмя направлениями; существующий самолёт не переименовывается в вертолёт.

## Порядок реализации и доказательства

1. Timeline/ownership: публичные pure tests строительства/удаления/переноса,
   быстрых стадий, старых/повторных событий, лимитов, скрытия/reduced motion.
2. Интеграция Pixi + бригада/дым/хлопок: MCP live status/delete, phase captures,
   сохранение старого вида до reveal, конечная стадия/руины, cleanup.
3. Грузовой арт + перенос: native/4× review, manifest/provenance/pack verification,
   MCP live transfer, old/new site, тросы/flight phases, отсутствие дублей.
4. Дорожные события: deterministic planner и tests closure/reopen, настоящее
   движение служб, безопасные пары/перекрёстки/полосы, bounded scene lifetime.
5. Звук/настройки: user gesture, mute/hidden/dispose, ограничение voices;
   реальные браузерные сценарии клавиатуры/touch и reduced motion.
6. Итог: strict types, lint, affected unit/integration, production build, asset
   audits, live desktop/tall/compact и повторные события/reconnect, performance,
   ревью fixed diff, документация и локальный пакет проверки. Внешние push/PR
   и выпуск требуют запроса, которого для этой новой цели нет.
   Не повторять несвязанные full горизонты.

## Критерии общей цели

- [x] AC-1: смена каждой стадии в CITY проходит через бригаду/пыль/reveal;
  сцена и карточка корректны при 1→2→3→4→5 и откате.
- [x] AC-2: live удаление показывает подготовку/снос/руины и не оставляет
  интерактивный старый объект, людей, звук или частицы.
- [x] AC-3: live перенос показывает настоящий authored helicopter с грузом,
  конечное размещение совпадает с сервером, прежнее место освобождается без нового постоянного маркера.
- [x] AC-4: ДТП/ремонт/пожар/медицинский вызов/патруль реально воспроизводятся,
  службы реагируют; закрытие и открытие дороги не нарушают движение и его safety.
- [x] AC-5: дубликаты, быстрые обновления, resync, смена города, скрытие,
  reduced motion/economy и звук проверены без зависаний/утечек/лишних запросов.
- [x] AC-6: стиль подтверждён native captures и audits; все live сценарии имеют
  доказательства. Проверены desktop 1440×1000/1100 и compact 390×844.
- [x] AC-7: измерения показывают bounded objects/heap/step cost; финальный diff
  отревьюен, документы согласованы, точная ревизия привязана к результатам.

## Риски и продолжение

Новая схема данных не нужна. Добавления к client invalidation внутренние и
обратно совместимы; старые события без optional metadata остаются допустимыми.
Настройки читают прежний localStorage v2 с безопасными defaults.
Откат — вернуть клиентские изменения/новую asset family, серверные данные не
переигрывать. Критический стоп: небезопасное движение, потеря актуальной стадии,
неограниченные эффекты, blur/посторонняя стилистика или незавершённый live test.

Локальный PostgreSQL после предыдущего аудита был недоступен из-за остановки
Docker Desktop. Этот внешний блок не мешает исходникам/pure tests/арту;
Для текущей цели поднят отдельный PostgreSQL14 на loopback55433 в .builder/living-city/pgdata; живые проверки идут на собственном runtime5208 и синтетических странах. Docker и пользовательский preview5207 не затронуты. Они не заменяются mock-тестами или нагрузкой публичной страны.
