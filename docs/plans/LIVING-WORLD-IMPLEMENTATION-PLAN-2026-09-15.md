Граф показывает технические зависимости, а не предписание запускать несколько агентов. P06 и проработка P07 могут выполняться раньше P03, если потребуется сперва исправить масштабные карты. До выбора личной/общей планеты P07 ограничен проектированием и прототипом без миграции.

Pxx — идентификаторы этапов этого плана. Прежние задачи 1–23 закрыты по приёмке пользователя. P01–P05 и P13 отслеживаются задачами 24–29; P06–P11 перенесены в задачи 30–35 в существующем районе 23 Версиограда. Точные IDs сохранены в living-world-tracking.json. ## 3. Вертикальные срезы

### P00. Зафиксировать baseline и бюджеты

Результат: повторяемый набор небольшого, обычного и большого мира, замеры исходной ревизии и измерительные точки новых слоёв. Нового арта нет.

Граница: существующие scripts/fixtures, rolling-performance-metric, ground-bake-budget, браузерные проверки. Новые инфраструктурные библиотеки и нагрузка на публичный сайт не требуются.

Проверка: одинаковый seed/набор данных между baseline и кандидатом; сохранены версия браузера, viewport, DPR, CPU/network profile, число видимых объектов, холодный/тёплый режим.

Выход: утверждённый измерениями baseline, а не обещание «стало быстрее» по одному открытию. Если текущая версия не достигает первоначальной абсолютной цели, это фиксируется до добавления эффектов и становится отдельным конкретным ограничением.

### P01. Районные состояния и временные знаки

Результат: обозначения PLANNED/ACTIVE/COMPLETED/ABANDONED, краткий контур, корректное снятие декора. Пакет A графики входит в этот срез.

Граница: district-territory, реестр WorldCanvas, минимальные агрегаты задач района, MapLegend. Ввести отдельную чистую функцию представления района и слой маркеров; не добавлять ещё один большой независимый renderer.

Проверка: пустой плановый район не создаёт blocks/roads; переход ACTIVE→PLANNED сохраняет здания; ACTIVE с завершёнными задачами не изображает стройку; нет места для знака — корректный fallback; отключение анимации; повтор/перестановка событий; переключение города.

Переиспользование: tests/district-territory.test.ts, district-switch-audit.test.ts, map-invalidation.test.ts; новый небольшой browser-сценарий жизненного цикла.

Зависит от P00. Готовность: выполнены AC-01, относящиеся пункты AC-11/12; визуально выбран один вариант знака.

### P02. «Мои» и режимы внимания

Результат: подсветка реальных участков, переключаемая прямо на карте; тестирование/дефекты/сроки в том же механизме, зависимости только по выбранной задаче.

Граница: лёгкий персональный HTTP read model, account-aware cache, map-invalidation, слой контуров, компактное меню. Назначение задачи не должно превращаться в SCENE-инвалидацию.

Проверка: один и тот же город у двух пользователей; назначение/снятие исполнителя; creator и forUser не считаются «Мои»; завершённые задачи включаются; ноль совпадений; срок наступает без другого события; ошибки страниц и смена snapshot revision; потеря членства; канонические footprints вместо bounds района.

При клике фильтра camera/worldVersion/число ground bakes неизменны. Панорамирование уже загруженного города не отправляет новых запросов фильтра. Допускается отдельная обновляемая сводка по другим масштабам без полных задач.

Переиспользование: map-invalidation-queue, map-scene-cache, task-detail-read; HTTP authorization tests. Доступность: toggle aria-pressed, клавиатура, видимый текст режима.

Зависит от P00. Готовность: AC-08; контракт приватности и обновления метаданных проверен.

Строительные материалы не меняют картинку земли каждый кадр. Рабочие не создаются по количеству всех задач и не пересоздаются от комментария. Событие завершения воспроизводится максимум один раз.

Переиспользование: construction-stage, task-incidents, city-mobility-safety, entity-reconciler; нативный art review.

### P07. Стабильная личная география

Результат: сохранённые материки/области стран не перемещаются после добавления задачи или изменения списка доступных стран.

Решение — личная планета. В актуальной пользовательской цели явно указана «стабильная личная география»; это закрепляет модель и снимает ранее открытый вопрос. Существующие CITY-координаты и гидрология сохраняются.

Граница: server geospatial layout storage, planet/country projections, версия раскладки, атомарный импорт прежнего вида пользователя, стабильные anchors городов. Существующие CITY-coordinates и гидрология не переписываются.

Проверка: 1→2→3→10 стран, изменение числа задач, удаление/повторное получение доступа, два одновременных первых запроса, повтор миграции, частично неудачный импорт, геометрическая ёмкость. Страны без доступа не присутствуют в DTO/ETag/подписях/кеше.

Идентичность маршрутов сохраняется при изменении видимости. Незанятые участки моря/сектора не раскрывают владельцев недоступных стран.

Переиспользование: planet-atlas-projection, planet-atlas-route, country-overview-projection, auth-routes. Новые DB-тесты allocator/idempotency/concurrency; изолированная rehearsal миграции.

Зависит от P00. Готовность: AC-06, согласованная ёмкость и обратимая активация нового read model.

### P08. Согласованный транспорт

Результат: один маршрут и фаза поездки для CITY/COUNTRY/PLANET, понятная карточка направления; поезд тормозит и стоит.

Граница: транспортный read model и persisted geometry, shared расписание, city-railway, city-micro-flights, country-railways, planet-surface-transport. Наземная CITY-ЖД остаётся прямой и отдельной от дорог.

Проверка: один/два готовых вокзала/аэропорта; разные материки; неподходящие стадии; удаление/перенос остановки во время движения; новое здание у рельсов; две вкладки; скрытие и возврат через пять минут; смена часов устройства компенсируется server epoch; частота отправления и стоянка.

Маршрут может иметь разную детализацию геометрии на масштабах. Его конечные города и фаза не могут противоречить друг другу. Расписание вычисляется без серверных покадровых записей.

Для личной планеты отдельно проверяются пользователи с разными наборами доступных стран: персональная проекция не раскрывает чужие остановки и не создаёт ЖД между разными материками ради общего routeId.

Переиспользование: city-railway, atlas-grid-transport, atlas-scene, atlas-aircraft, atlas-ship-path и browser city-railway/atlas-transport. Полный 24-часовой прогон симуляции не нужен.

Зависит от P07. Готовность: AC-04 для ЖД/авиа, отсутствие пересечений и сохранность исторического плана.

### P09. Порт и морской маршрут

Результат: один осмысленный порт приморского города, стадии терминала/пирса, суда между готовыми портами разных материков. Пакет C.

Граница: новая PORT-role, каталог и policy, береговой план/резервы, shared water routing, DTO/MCP enum consumers, art/scene loaders, панель развития.

Проверка: связный океан против озера, сухопутный город, нет подходящего участка, явное и автоматическое назначение, два конкурирующих запроса, уникальность, стадии 1–5, ширина корпуса у берега и швартовки, отсутствие маршрута без второго порта.

Отдельный сценарий — вода есть в CITY, но не доказана её связь с океаном атласа: выдачи порта и морского рейса нет. Береговой план содержит проверяемую связь локального водного выхода с географией P07.

Старые города не получают перемещённых задач или принудительных каналов. Выдача новых портов включается отдельно от чтения уже размещённых.

Переиспользование: catalog/asset audit, world-audit-blocks, intercity-road planning patterns, atlas-grid-transport. Новая роль требует проверки всех consumers, даже если её не показывают отдельным MCP-инструментом.

Зависит от P04 и P08. Готовность: AC-04 для моря, AC-11/12 и корректная причина невозможности разместить порт.

### P10. «С прошлого посещения»

Результат: ограниченная сводка новых завершений, дефектов и открытий; переход к зданию без автоматического тура.

Граница: существующий event log и coalesced refresh, ограниченный summary endpoint, локальный просмотренный курсор, навигация к задачам/участкам. Максимум 20 подробных карточек; большие серии агрегируются.

Проверка: первый вход, повторное подключение, старый курсор, несколько вкладок, удалённая/перенесённая задача, выход из аккаунта, отзыв доступа, событие за пределами периода, timezone. Просмотренный курсор обновляется после успешного показа, а не после одного сетевого запроса.

Переиспользование: realtime-notifications, coalesced-refresh, task-navigation, SiteHistoryModal. Поздравления не повторяются при replay.

Зависит от P02 и P05. Готовность: AC-09.

### P11. Качество, время суток и финальная оптимизация слоёв

Результат: автоматическое/обычное/экономное качество, реальное время/всегда день; карта сохраняет чёткость и интерактивность.

Граница: существующая telemetry, animation lifecycle, texture ownership, camera projection caches, world-light-clock; локальные предпочтения. Логический шаг дорожной симуляции и бизнес-состояние не меняются.

Автоматическое качество использует устойчивое окно измерений и гистерезис: сначала снижает рабочих/частицы/облачную анимацию; повышение возможно после длительного стабильного окна. Не реагирует на один долгий кадр загрузки. Первичные кандидаты: 8→2 дополнительных рабочих, 2→1 реакция завершения, статичные дальние эффекты.

Проверка: переключение во время движения/загрузки, prefers-reduced-motion, background/foreground, высокое DPR, долгий сеанс, отключённое localStorage, отсутствие колебаний качества. Качество не удаляет задачи и важные маркеры.

Измерения используют наборы P00 и tracing конкретного узкого места. Готовность: AC-10; результаты отдельно для первой загрузки, тёплого перехода и движения камеры.

Зависит от P01/P02/P03/P05/P06/P08/P09/P10. Бюджеты проверяются в каждом предыдущем срезе, не откладываются до P11.

### P12. Общая приёмка и подготовка релиза

Результат: согласованные функции в одной проверенной ревизии, документы и план отката. Сам релиз выполняется только как отдельный разрешённый этап.

Проверка: все AC, выбранная браузерная матрица, типы/lint/build, затронутые unit/integration, assets, HTTP/MCP compatibility, review diff и старых путей. Полный обязательный SCM gate один раз на финальном кандидате.

Миграции проверяются на изолированной копии с сохранностью business rows/ID/history. PWA проверяется переходом между старой и новой версиями с CDN/worker-контрактом. Новые необязательные спрайты не расширяют критический precache всего приложения.

Обновить WORLD-GENERATION/ARCHITECTURE/QA/BUILDINGS и документы арта. Старые схемы оставить только как помеченный архив; исправить легенду и инструкции о неподключённом runtime.

Зависит от P03/P04/P09/P10/P11. Готовность: все AC выполнены либо конкретное изменение объёма согласовано, а не скрыто в skipped.

## 4. Начальные бюджеты и метод измерения

Ниже целевые бюджеты для прототипа, не результаты выполненных тестов. P00 фиксирует baseline и при необходимости явную корректировку цели до расширения эффектов.

Наборы:

- S: 30 задач, 2 района, 2 города.
- M: 300 задач в основном городе, 12 районов, 6 городов в 3 доступных странах.
- L: 2000 задач в основном городе, 60 районов, 20 городов в 10 доступных странах.
- Для M/L распределение задач: 80% завершены, 15% в работе, 5% на проверке/планировании; отдельный стресс-кейс — много одновременных строек. Включить 20 уникальных семейств и исторические участки.

Браузеры: Chromium desktop 1440×900 DPR1/2; мобильный Chromium 390×844 DPR2 с фиксированным CPU-профилем; WebKit — функциональные сценарии canvas/pointer/PWA и визуальное сравнение. Реальный мобильный замер отмечается отдельно от эмуляции.

Холодный запуск: очищены app/asset caches и новый сеанс; сеть 50 Mbit/s, RTT80ms. Тёплый переход: уже загружены обе сцены и общие ресурсы. Собирать минимум 20 холодных и 50 тёплых проб для M; для L — минимум 10 холодных/30 тёплых, указывать меньшую надёжность p95. Не запускать такую серию на общем сервере.

| Метрика | Начальная цель |
| --- | --- |
| Включение кешированной подсветки M | p95 ≤50ms desktop, ≤100ms mobile |
| Тёплый переход M | p95 ≤300ms desktop, ≤600ms mobile |
| Первый интерактивный CITY M | p95 ≤4s desktop, ≤6s mobile |
| COUNTRY/PLANET M из готового приложения | p95 ≤1,5s desktop, ≤3s mobile |
| Движение камеры | p95 frame ≤20ms desktop, ≤1000/30ms mobile (30fps; первоначальные33ms были округлением); без серии зависаний >100ms |
| Дополнительные слои после подготовки | p95 CPU ≤2ms desktop; деградация обычного кадра не более 10% от baseline |
| Декоративные рабочие | ≤8 видимых / ≤2 экономный / 0 reduced-motion |
| Миниатюра | ≤12 основных объектов + ≤3 транспортных ориентиров на город |
| Сеть при pan/zoom/анимации | 0 новых запросов основной сцены из-за новых функций |
| Утечки | После 30 переходов нет монотонного роста живых views/textures/listeners; память после стабилизации ≤baseline+15% |

Для L сравнивать с baseline и проверять жёсткие лимиты объектов; если бюджет не достигнут, поднимать блокирующее конкретное узкое место. Нельзя объявить готовность только потому, что S быстрый.

Строительные декорации не блокируют первый кадр. Отсутствующая необязательная картинка не вызывает общий retry сцены. Проекция статичной географии вычисляется по revision; камера меняет transform/culling, а не повторно выбирает маршруты и здания.

## 5. Контрактная совместимость и выпуск

Итоговая реализация подготовлена одним изменением сервера, клиента и каталога.
Первоначальное предложение выпускать срезы через отдельные флаги и dual-read не
применялось: таких переключателей в конфигурации нет. Их наличие не должно
подразумеваться в будущем релизном плане.

Миграции0030–0035 аддитивны для бизнес-данных: отдельные preview/index/geography/railway
таблицы, допустимая рольPORT и nullableterrain_profile. Старые страны сохраняютNULL,
новыйCOASTALпрофиль задаётся только при создании страны. Существующие планы CITY не
перегенерируются. Первый импорт личной географии атомарен и далее только расширяется.
Новые DTOполя необязательны для чтения; это не обещание совместимости старого
каталога с новыми зданиями.

Будущий выпуск: один проверенный SHA и его согласованные web/MCP/worker/ассеты,
обновление PWA штатной кнопкой, затем smoke CITY/COUNTRY/PLANET, задач и OGссылок.
Старый клиент должен обновиться перед открытием новогоPORT: его локальный каталог
не знает это семейство. Смешанная выкладка нового сервера со старым каталогом не
является поддерживаемым режимом.

Возврат старого образа после появления PORT/новых профилей нельзя считать безопасным.
До возобновления записи допустимо восстановить проверенные предыдущие БД и образ
вместе по runbook. После новых пользовательских записей допустимо исправление вперёд
с сохранением новой схемы; восстановление старого dump поверх новых задач запрещено.
Нельзя откатывать географию пересозданием раскладки или удалять сохранённые резервы.
Локальные upgrade/recoveryтесты проверяют сохранность данных, но не заменяют backup
целевого сервера. Конкретный preflight/rollbackmanifest привязывается к SHA при
отдельной авторизации релиза через [DEPLOYMENT](../DEPLOYMENT.md).

Стоп-условия: изменение сохранённых footprints; утечка чужих стран/назначений; сдвиг старых областей при росте; несогласованные endpoints; повторные долгие зависания; размытые или неправильно зарегистрированные спрайты; восстановление требует потери новых данных.

Релизная цель при будущем разрешении — установленный managed-release target, точный итоговый SHA, проверка SCM и штатный updater. Настоящий документ не является новой командой выкладки.

## 6. Проверка самого плана

- Все восемь направлений аудита покрыты критериями AC-01…AC-12.
- Уточнения пользователя о временных районных спрайтах, «Мои» на карте и оптимизации включены явно.
- Порядок зависимостей записан в JSON для локальной проверки отсутствия циклов.
- План арта ограничивает первый заказ и связывает каждый пакет с пользовательским срезом.
- Приёмка не зависит от массовой перегенерации; сохранность существующих участков проверяется отдельно.
- Открытая развилка географии отделена от готовых к первому прототипу районных маркеров и фильтров.

### P13. OG-превью задачи (дополнение пользователя)

Задача Tasktopia №25 (8c2d81f9-a3cd-44ad-805a-acc582a3869f), входит в общую цель реализации. Результат: общая ссылка показывает номер, название и краткое описание в первом серверном HTML-ответе, без JavaScript.

Публикация только через явное действие «Поделиться» с отзывом ограниченного превью. Обычные приватные адреса не раскрывают содержимое; переход к самой задаче сохраняет авторизацию. Контроль HTML-экранирования, длины, канонического origin, удаления, отзыва и кешей. Проверки: HTTP для анонимного/чужого/авторизованного пользователя, браузер копирования и открытия ссылки.

Зависит от P00; итоговая приёмка P12 включает P13. Исполнитель — текущая сессия Codex, срок не назначен.
