# QA 1.4 — жизненный цикл и живой мир

## Автоматические проверки

```bash
npm run typecheck
npm run lint
npm test
npm run assets:build && npm run assets:verify
npm run build
DATABASE_URL=postgres://tasktopia:tasktopia@127.0.0.1:55432/tasktopia_test npm run test:e2e
```

Scale-профиль остаётся отдельным opt-in запуском и не входит в обычный параллельный suite.

## Ручная проверка малого мира

1. Создать один город и до десяти районов; не создавать массовый набор городов.
2. Установить району `capacitySp: 3`, создать задачи суммой больше 3 SP и убедиться, что сервер не блокирует размещение.
3. Удалить задачу через `task.delete` с неправильным, затем точным `confirmTitle`; участок должен освободиться. Повтор с тем же idempotency key возвращает тот же результат.
4. Удалить активный район через `district.delete`; проверить каскад задач и автоматическую активацию следующего планового района.
5. Удалить тестовый город через `city.delete`; проверить отсутствие его районов, задач, features и chunk-index записей.
6. Включить границы: активный район должен отличаться толстой рамкой и жёлтым флагом.
7. Сравнить несколько районов: улица/ряды зеркалятся, ограждения редкие и не перекрывают входы.
8. Проверить прямые зебры между тротуарами и отсутствие переходов на мостах, highway, поворотах и расширениях перекрёстков.
9. Найти у воды рыбака и деревянную лодку; лодка находится в глубокой воде дальше от берега, рыбак — на сухом берегу. Water-вариант с рыбой остаётся редким.
10. Проверить фонари и разные действия жителей возле городской пешеходной сети; люди не проходят через полный footprint забора/декора.
11. Навести на нижний badge здания: tooltip показывает название, статус, процент и короткое описание; клик по зданию по-прежнему открывает задачу.
12. Панорамировать и масштабировать карту: overview не грузит detail-декор, нет чёрных следов, зависаний и повторного запроса уже резидентных чанков.
